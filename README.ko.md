**이미 쓰고 있는 코딩 에이전트(Claude Code, Codex, OpenCode, Antigravity, Pi CLI)를 위한 시각적 작업 공간입니다.** 내 컴퓨터에서 실행되고 브라우저에서 열립니다. 이미 설치하고 로그인해 둔 CLI를 그대로 사용하며, 자격 증명에는 절대 손대지 않고, 앱 자체에서는 어떤 네트워크 요청도 보내지 않습니다.

```bash
npx agent-workbench
```

## 작동 방식

Agent Workbench는 어떤 AI 서비스와도 통신하지 않습니다. 이미 설치된 CLI(`claude`, `codex`, `opencode`, `agy`, `pi`)를 실제 터미널 안에서 실행하고, 터미널만으로는 얻을 수 없는 것들을 그 주위에 더합니다. 탭, 지난 대화, 읽기 쉬운 카드로 정리된 대화, 컨텍스트 미터, 변경된 파일, 파일 트리가 그것입니다.

터미널은 여전히 터미널입니다. 입력하는 모든 내용은 곧바로 CLI로 전달됩니다.

## 주요 기능

| | |
|---|---|
| **탭** | 어떤 CLI든 여러 에이전트를 동시에, 각자의 폴더에서 실행합니다. 탭마다 있는 점을 보면 에이전트가 작업 중인지, 쉬고 있는지, 내 응답을 기다리는지 알 수 있습니다. 페이지를 새로 고쳐도 아무것도 멈추지 않습니다. CLI는 브라우저가 아니라 서버에서 실행되기 때문입니다. |
| **빠른 시작** | 앱을 열면 탭이 **절전 중** 상태로 돌아옵니다. 내용은 전부 읽을 수 있고, **CLI 열기**를 클릭하기 전에는 어떤 CLI도 시작되지 않습니다. |
| **기록** | 모든 CLI의 프로젝트와 지난 대화가 사이드바에 필터와 함께 표시됩니다. 하나를 클릭하면 그 CLI로 멈췄던 곳부터 이어서 진행합니다. 오래된 세션이나 프로젝트 전체를 보관해 목록을 정리할 수 있습니다. 아무것도 삭제되지 않으며 되돌릴 수도 있습니다. |
| **대화** | 메시지가 실시간으로 카드처럼 표시되고, 도구 호출은 접혀 있습니다. 위로 스크롤하면 이전 메시지를 불러옵니다. 검색하고, 어떤 메시지나 코드 블록이든 복사하고, 내 이전 메시지(↑)나 맨 끝(↓)으로 이동할 수 있습니다. 아래쪽 줄에는 메시지가 언제 CLI에 전달되었는지, 에이전트가 아직 작업 중인지가 표시됩니다. CLI에 따라서는 에이전트의 질문에 그 자리에서 답할 수도 있습니다. 에이전트가 언급한 프로젝트 파일은 클릭 한 번으로 파일 탭에서 열 수 있고, 폴더는 시스템 파일 탐색기에서 열립니다. Claude Code에서는 에이전트가 시작하기 전에 멈춘 메시지가 입력창으로 돌아와 고칠 수 있고, 메시지의 **↩** 버튼으로 그 메시지 이전으로 되돌아갈 수 있습니다(대화와, 원하면 코드까지). 에이전트가 작업하는 동안 보낸 메시지는 대기 중으로 표시되어 끝에서 기다리며, CLI에 따라 **지금 강제로 보내기** 버튼으로 에이전트가 바로 읽게 할 수 있고, **편집** 버튼(또는 빈 입력창에서 ↑)을 누르면 메시지가 입력창으로 돌아와 고칠 수 있습니다. |
| **입력창** | 넉넉한 공간에 글을 쓰고, 이미지를 붙여 넣고, 파일을 첨부할 수 있습니다. 길게 붙여 넣은 텍스트는 깔끔한 칩으로 정리됩니다. 입력 중인 내용은 앱을 닫아도 남아 있고, 열려 있는 모든 창에 실시간으로 나타납니다.Shift+Enter로 번호 목록이나 글머리 기호 목록을 이어 쓸 수 있습니다. Claude Code에서는 시계 버튼으로, 쓴 내용을 고른 날짜와 시간에 같은 대화로 자동으로 보낼 수 있습니다(⚙ 설정에서 켭니다). |
| **컨텍스트 미터** | 대화가 모델의 컨텍스트 윈도우를 얼마나 쓰고 있는지 보여 줍니다. 비용이 아니라 토큰으로만 표시합니다. 70%부터는 **압축** 버튼으로 CLI에 대화 압축을 요청할 수 있습니다. Claude Code, Codex, Antigravity CLI에서는 그 옆에 요금제 사용 한도를 얼마나 썼는지와 언제 초기화되는지도 표시됩니다. |
| **변경 사항** | 브랜치, 변경된 파일, 그 diff를 보여 줍니다. **에이전트를 병렬로 돌립니다.** 프로젝트를 새 브랜치로 자기 폴더에 열면, 여러 에이전트가 서로의 변경을 밟지 않고 동시에 작업합니다. 변경 사항에서 각 브랜치의 상태를 봅니다: 커밋하지 않은 것, 커밋 수, 통합 여부. 다른 CLI가 브랜치를 건드리지 않고 리뷰하고, 클릭 한 번으로 main에 통합합니다. |
| **파일** | 프로젝트의 파일 트리로, 검색과 구문 강조 미리 보기를 지원합니다. 여러 파일을 각자의 탭에서 동시에 열 수 있고, Markdown 파일은 서식이 적용된 상태로 열립니다. 클릭 한 번으로 파일 경로를 메시지에 넣을 수 있습니다.텍스트 파일(예: `.env`)을 그 자리에서 편집하고 저장할 수 있습니다. 편집하는 동안 에이전트가 파일을 바꿨다면 아무것도 덮어쓰지 않으며, 내 변경 사항을 새 버전으로 옮기면 됩니다. |
| **계획** | 대화에서 작성한 계획과 `.md` 문서를 렌더링해서 보여 줍니다. 클릭 한 번으로 문서 경로를 메시지에 넣을 수 있습니다. |
| **메모** | 대화 옆에 두는 메모장으로, 이미지도 넣을 수 있습니다. **입력창으로**를 누르면 메모가 입력창에 들어가 지금 대화로 보낼 수 있고, Claude Code에서는 클릭 한 번으로 새 대화로 보낼 수도 있습니다. |
| **콘솔** | 화면 아래쪽에서 프로젝트 폴더를 기준으로 여는 시스템 터미널입니다. Windows에서는 PowerShell, cmd, Git Bash를, macOS와 Linux에서는 bash나 zsh를 씁니다. |
| **다음 CLI에서 계속** | CLI가 두 개 이상이면 같은 폴더에서 다른 CLI로 대화를 이어 갈 수 있습니다. 새 에이전트는 최근 턴들의 트랜스크립트에서 시작합니다. |
| **알림** | 에이전트가 작업을 마치거나 내 응답을 기다리면 소리로 알려 주고, 원하면 시스템 알림도 보냅니다. |
| **설정** | 헤더의 ⚙에서 언어, 터미널 테마, 표시할 패널, 열 콘솔, 앱이 사용할 CLI, 메시지 보내기 예약 여부를 고릅니다. |
| **9개 언어** | English, Español, 简体中文, 日本語, Português (Brasil), Русский, 한국어, Français, Deutsch. 브라우저 언어를 따릅니다. |
| **테마** | 밝은 테마, 어두운 테마, 시스템 테마 중에서 고릅니다. 터미널은 기본적으로 어둡게 유지되어 CLI의 색상이 잘 보입니다. |

선택 사항이며 기본적으로 꺼져 있는 기능도 있습니다. CLI 간 [공유 메모리](#cli-간-공유-메모리), 기록 [백업](#기록-백업), Claude Code의 [요금제 사용 한도](#claude-code-요금제-사용-한도), 다른 컴퓨터나 휴대폰에서 쓰는 [원격 접속](#ssh를-통한-원격-접속), [Android 앱](#android-앱)입니다.

### CLI를 여러 개 사용할 때

세션과 탭마다 해당 CLI를 나타내는 작은 배지가 붙고, 새 탭을 여는 `+`에서 어떤 CLI를 열지 고를 수 있습니다. CLI가 하나뿐이면 이런 표시는 보이지 않습니다.

<img src="assets/captura-clis.png" width="45%" alt="여러 CLI의 세션이 각자의 배지와 함께 나오는 프로젝트 사이드바, 그리고 다섯 CLI와 각 버전이 나오는 + 메뉴">

**모든 CLI가 같은 정보를 제공하지는 않기 때문에** 일부 기능은 CLI에 따라 다릅니다.

| | Claude Code | Codex | OpenCode | Antigravity CLI | Pi |
|---|:---:|:---:|:---:|:---:|:---:|
| 탭의 점: 작업 중, 쉬는 중, 내 응답 대기 | ✓ | — | ✓ ¹ | ✓ ² | ✓ |
| 대화에서 에이전트의 질문에 답하기 | ✓ | — | ✓ ¹ | — | — |
| 컨텍스트 미터 | ✓ | ✓ | ✓ | ✓ ² | ✓ |
| 모드와 모델 선택 | ✓ | — | — | ✓ | ✓ ³ |
| 이미지 붙여 넣기 | ✓ | ✓ | ✓ | — | ✓ ³ |
| 계획 탭 | ✓ | — | — | — | — |
| 메모를 새 대화로 보내기 | ✓ | — | — | — | — |

나머지는 언제든 CLI 자체 터미널에서 할 수 있습니다. 예를 들어 "—"로 표시된 곳에서는 질문에 그 터미널에서 답합니다.

¹ OpenCode에서는 이 정보를 얻으려고 앱이 로컬 OpenCode 서버를 실행합니다([자세히](#데이터와-보안)).
² 상태 표시줄을 설정한 경우에만 가능합니다([방법](#antigravity-cli-상태와-컨텍스트-미터)).
³ Pi에는 권한 모드가 없어서, 선택할 수 있는 것은 모델과 사고 수준입니다. 또 붙여 넣은 것을 첨부하지 않습니다. 이미지는 파일 경로로 전달되고, 모델이 그 파일을 직접 엽니다.

## 요구 사항

- **Node.js 20 이상.** OpenCode의 기록과 Antigravity CLI의 대화 제목을 보려면 **22.13 이상**이 필요합니다. 이 버전부터 Node에 내장된 SQLite로 읽기 때문입니다. 그보다 낮은 버전에서도 나머지 기능은 모두 작동합니다.
- **git**: 변경 사항 패널에 필요합니다. 없어도 나머지 기능은 모두 작동합니다.
- **CLI 하나 이상**: 설치하고 로그인해 두어야 합니다.

| CLI | 명령 | 설치 방법 |
|---|---|---|
| Claude Code | `claude` | [설치 가이드](https://docs.claude.com/en/docs/claude-code/setup) |
| Codex | `codex` | [가이드](https://learn.chatgpt.com/docs/codex/cli) |
| OpenCode | `opencode` | [문서](https://opencode.ai/docs/) |
| Antigravity CLI | `agy` | [가이드](https://antigravity.google/docs/cli/getting-started) |
| Pi | `pi` | [pi.dev](https://pi.dev) |

Agent Workbench는 어떤 CLI도 포함하거나 다운로드하지 않으며, `PATH`에 있는 CLI를 찾아서 씁니다. 하나도 없으면 그렇다고 알려 주고 세션을 열지 않습니다.

**플랫폼.** Windows 11과 PowerShell 환경에서 개발하고 매일 사용합니다. macOS와 Linux에서도 변경할 때마다 자동으로 설치하고 실행해 보지만, 일상적으로 쓰는 일은 더 적습니다. 제보를 환영합니다. Linux에서는 설치할 때 터미널 모듈을 컴파일하므로 `python3`, `make`, C++ 컴파일러(Debian과 Ubuntu에서는 `build-essential`)가 필요합니다.

## 설치와 실행

```bash
npm install -g agent-workbench
```

그다음 작업할 프로젝트 폴더에서 실행합니다.

```bash
agent-workbench
```

브라우저가 다음과 같은 주소로 열립니다.

```
  URL          http://127.0.0.1:52341/?token=…
```

이 주소가 유일한 입구입니다. 토큰은 실행할 때마다 바뀌고, 앱은 내 컴퓨터(`127.0.0.1`)에서만 연결을 받습니다.

설치하지 않고 한 번 써 보려면 `npx agent-workbench`를 실행하세요. 처음에는 약 60 MB를 내려받는데, 대부분 터미널의 네이티브 모듈입니다. 매일 쓴다면 전역 설치가 더 낫습니다.

## 키보드 단축키

| 키 | 동작 |
|---|---|
| `Alt+T` | 새 탭 |
| `Alt+W` | 탭 닫기 |
| `Alt+←` / `Alt+→` (또는 `Alt+PgUp` / `Alt+PgDn`) | 이전 / 다음 탭 |
| `Alt+P` | 오른쪽 패널 표시 또는 숨기기 |
| `Shift+Tab` (터미널 밖에서) | 이전 탭으로 돌아가기 |

헤더의 `?` 버튼을 누르면 이 단축키 전부와 현재 CLI의 자체 단축키를 볼 수 있습니다. `Alt`를 쓰는 이유는 브라우저가 `Ctrl+T`, `Ctrl+W`, `Ctrl+Tab`을 자체 탭용으로 쓰고 페이지에는 전혀 전달하지 않기 때문입니다.

나머지 키(`Esc`, `Ctrl+C`, `Ctrl+R`, `Ctrl+O`, 화살표 키, 이미지를 붙여 넣는 `Alt+V`)는 모두 그대로 CLI에 전달됩니다. `Ctrl+V`도 마찬가지이며, 이 키로 무엇을 할지는 CLI가 정합니다. Windows의 아래쪽 콘솔에서만 Windows Terminal처럼 `Ctrl+V`로 텍스트를 붙여 넣습니다.

## 선택 기능

### CLI 간 공유 메모리

CLI는 프로젝트에 대해 알게 된 내용을 각자의 위치에 저장하므로, 다른 CLI는 그 내용을 볼 수 없습니다. **메모리** 탭은 모든 CLI가 함께 쓰는 메모리 하나를 설정합니다. 프로젝트의 `.agents/memory/` 폴더에 노트를 두고, 모든 CLI가 (여기서든 자체 터미널에서든) `AGENTS.md`와 `CLAUDE.md`를 통해 이 노트를 읽고 씁니다. 이 탭은 처음에는 숨겨져 있으니 ⚙ 설정에서 표시하세요.

**변경 사항 미리 보기**는 무엇이 기록될지 파일별로 보여 주며, 확인하기 전에는 아무것도 건드리지 않습니다. 설정하면 Claude Code가 그 프로젝트에 대해 이미 가지고 있던 메모리도 가져옵니다. 앱은 각 CLI의 전역 설정을 편집하지 않고, 직접 붙여 넣을 스니펫을 보여 줍니다.

### 기록 백업

각 CLI의 기록은 그 CLI가 관리하므로, CLI가 형식을 바꾸거나 기록을 정리해 줄일 수 있고, CLI 자체가 제거될 수도 있습니다. 백업은 대화의 사본(메시지, 도구 호출과 결과, 이미지, 각 프로젝트의 메모리)을 사용자의 폴더에, 앱 없이도 읽을 수 있는 파일로 보관합니다.

**기본적으로 꺼져 있습니다.** 프로젝트 사이드바 상단의 백업 버튼이나 ⚙ 설정에서 엽니다. **측정**은 아무것도 쓰지 않고 CLI별로 공간이 얼마나 필요한지 알려 주고, **켜기**를 누르면 백업이 시작됩니다. 그 뒤로는 사이드바에서 보관되지 않은 모든 항목을 복사하고, 대화가 더 이상 바뀌지 않은 채 1분이 지나면 그 대화를 다시 복사합니다. 그 폴더에서는 아무것도 삭제하지 않습니다.

백업을 켜면:

- CLI에 더 이상 없는 대화도 백업 표시와 함께 사이드바에 남고, Markdown으로 열립니다.
- 어떤 프로젝트든 Markdown으로 내보낼 수 있습니다.
- CLI가 두 개 이상이면 사이드바 필터에서 **대화에서**를 골라, 모든 CLI에서 복사된 모든 내용의 텍스트를 검색할 수 있습니다.

<img src="assets/captura-buscador.png" width="40%" alt="대화 검색: CLI마다 세션 하나에서 찾은 일치 항목과 발췌">

기본 위치는 앱의 설정 폴더(Windows에서는 `%APPDATA%\agent-workbench\vault`)입니다. **폴더 변경…** 버튼은 백업을 동기화 폴더나 다른 드라이브 같은 다른 폴더로 아무것도 덮어쓰지 않고 복사하며, 기존 폴더는 그대로 둡니다. 동기화 폴더나 저장소에 두면 대화 내용도 함께 전송됩니다.

### Claude Code: 요금제 사용 한도

Claude Code는 요금제 사용 한도(5시간 창과 주간)를 얼마나 썼는지 *상태 표시줄*을 통해서만 알려 줍니다. 이 한도를 컨텍스트 미터 옆에 표시하는 방법은 다음과 같습니다.

1. Claude Code 탭을 열고 미터 옆의 **설정**을 클릭합니다.
2. 표시되는 줄을 복사해 `~/.claude/settings.json`에 이미 있는 내용에 추가합니다. 앱은 이 파일을 편집하지 않으니 직접 편집하세요.
3. 몇 초 안에, 또는 **확인**을 누르면 대화 상자에 **설정됨**이 표시됩니다. 한도는 다음 응답과 함께 나타납니다.

Claude Code는 상태 표시줄을 하나만 쓸 수 있으므로 이 상태 표시줄이 기존 것을 대체하며, 그러면 CLI가 하단에 표시하던 일부 도움말(예: "esc to interrupt")이 더 이상 나오지 않습니다. 이 줄은 앱 자체 폴더에 있는 작은 스크립트를 실행합니다. 스크립트는 두 한도와 세션 ID만 저장하고, 이를 CLI 하단에 짧은 한 줄로 표시합니다. 앱 밖에서 연 세션을 포함해 **모든** `claude` 세션에서 실행되며, `PATH`에 `node`가 있어야 합니다. Claude Code는 이 한도를 API 키가 아니라 구독 요금제에서만 제공합니다.

Codex는 설정할 것이 없습니다. 자체 기록에 한도를 남기기 때문입니다. Antigravity CLI는 아래에서 설명하는 상태 표시줄로 한도를 보여 줍니다. OpenCode와 Pi는 한도를 제공하지 않습니다.

### Antigravity CLI: 상태와 컨텍스트 미터

Antigravity CLI는 작업 중인지 내 응답을 기다리는지, 토큰을 얼마나 썼는지, 할당량이 얼마나 남았는지를 *상태 표시줄*을 통해서만 알려 줍니다. 상태 표시줄이 없어도 탭은 정상적으로 작동하지만, 탭의 점은 상태를 알 수 없다고 표시하고 미터는 모두 비어 있습니다. 켜는 방법은 다음과 같습니다.

1. Antigravity 탭을 열고 미터 옆의 **설정**을 클릭합니다.
2. 표시되는 줄을 복사해 `~/.gemini/antigravity-cli/settings.json`에 이미 있는 내용에 추가합니다. 앱은 이 파일을 편집하지 않으니 직접 편집하세요.
3. 몇 초 안에, 또는 **확인**을 누르면 대화 상자에 **설정됨**이 표시됩니다.

이 줄은 앱 자체 폴더에 있는 작은 스크립트를 실행합니다. 스크립트는 각 대화의 상태, 모드, 모델, 토큰만 저장하고, 할당량은 얼마나 남았는지와 언제 초기화되는지만 저장합니다. CLI가 함께 넘겨주는 이메일, 요금제, 비용은 저장하지 않으며, 아무것도 출력하지 않으므로 CLI 자체 상태 표시줄은 그대로 유지됩니다. 한 번 설정하면 앱 밖에서 연 세션을 포함해 **모든** `agy` 세션에서 실행되며, `PATH`에 `node`가 있어야 합니다.

### SSH를 통한 원격 접속

한 컴퓨터에서 Agent Workbench를 실행해 두고, 같은 네트워크에 있는 다른 컴퓨터의 브라우저에서 사용할 수 있습니다. 그 컴퓨터에는 CLI가 없어도 됩니다. **앱이 네트워크에 열리는 일은 없습니다.** 앱은 여전히 `127.0.0.1`에서만 연결을 받고, 다른 컴퓨터는 SSH 터널을 통해 접속합니다. 이 방식이 제대로 작동하는 것도 터널 덕분입니다. 터널을 거치면 다른 컴퓨터의 브라우저가 앱을 `localhost`로 인식하는데, 브라우저는 클립보드와 알림을 이런 주소에서만 허용합니다. **기본적으로 꺼져 있습니다.**

**1. 앱을 실행하는 컴퓨터에서, 한 번만: SSH 서버를 켭니다.** 관리자 권한이 필요한 시스템 변경이라 앱이 대신 하지 않습니다.

- **Windows 10/11** — *관리자 권한으로* 연 PowerShell에서 실행합니다. 첫 줄은 서버를 내려받아 설치하므로 몇 분 걸립니다. 프롬프트가 다시 나타날 때까지 기다리세요.

  ```powershell
  Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
  Start-Service sshd
  Set-Service -Name sshd -StartupType Automatic
  ```

- **macOS** — 시스템 설정 → 일반 → 공유 → **원격 로그인**.
- **Linux** — 배포판의 OpenSSH 서버를 설치하고 켭니다. Debian이나 Ubuntu에서는:

  ```bash
  sudo apt install openssh-server
  sudo systemctl enable --now ssh
  ```

**2. 앱에서: 헤더의 ⇄ → 원격 접속 켜기를 누른 뒤 Agent Workbench를 다시 시작합니다.** 터널에는 바뀌지 않는 포트가 필요하므로 앱은 고정 포트(기본값 24837, 변경 가능)를 쓰며, 포트는 시작할 때 정해집니다. 다시 시작하면 열려 있던 CLI가 닫히고, 탭은 절전 중 상태로 돌아옵니다. *끄는* 것은 바로 적용됩니다.

**3. 다른 컴퓨터에서, 사용할 때마다: 터널을 엽니다.** 대화 상자에 바로 복사할 수 있는 명령이 나옵니다.

```
ssh -N -L 24837:127.0.0.1:24837 you@your-computer
```

이 명령은 계속 실행해 두고, **양쪽 끝에 같은 포트를 쓰세요**. 로컬 포트가 다르면 앱이 403으로 응답합니다. `-o ServerAliveInterval=30 -o ExitOnForwardFailure=yes`를 추가하면 Wi‑Fi가 끊겼을 때 터널이 멈춰 있지 않고 끊김을 알아챕니다. Windows에서는 이 명령을 `.cmd` 파일로 저장해 두고 더블클릭해서 실행할 수 있습니다.

**4. 그 컴퓨터를 한 번만 페어링합니다.** 대화 상자에서 **기기 페어링**을 누르면 `http://localhost:24837/?pair=K7QM-X2RD`처럼 일회용 코드가 붙은 주소가 나옵니다. 5분 안에 다른 컴퓨터의 브라우저에서 이 주소를 여세요. 그 뒤로는 앱이 다시 시작되더라도 그 브라우저에서 `http://localhost:24837`만 열면 됩니다. 대화 상자에는 페어링된 기기 목록이 나오며, **권한 취소**를 누르면 그 기기의 접속이 즉시 끊깁니다.

페어링된 기기는 원격 접속 관리와, *기본 앱으로 열기*처럼 앱을 실행 중인 컴퓨터에 창을 여는 몇 가지 기능을 빼고 앱 전체를 쓸 수 있습니다. 이런 기기에서는 헤더에 **원격** 배지가 표시됩니다. 앱에는 콘솔이 있고 에이전트를 실행하므로, 페어링된 기기도 나와 마찬가지로 내 컴퓨터에서 명령을 실행할 수 있다는 점을 기억하세요. **본인 소유의 기기만 페어링하세요.**

**휴대폰이나 태블릿에서.** 같은 터널을 통해 휴대폰 브라우저에서는 한 열짜리 레이아웃이 나옵니다. 프로젝트 사이드바는 옆에서 밀려 나오고, 탭은 헤더에 있으며, 전환 바로 대화, CLI, 변경 사항, 파일 등을 오갑니다. 이 레이아웃은 너비가 768 px보다 좁은 창이면 어디서든 나타납니다. 터치스크린에서는 입력창에서 Enter를 누르면 줄이 바뀌고(보내려면 보내기 버튼을 누릅니다), 터미널 위에서 손가락을 끌면 스크롤됩니다.

<details>
<summary>터널에만 쓸 수 있는 더 안전한 SSH 키(권장)</summary>

SSH 로그인은 그 컴퓨터에 있는 내 사용자 계정으로 이루어지므로, 터널을 여는 비밀번호나 키로 그 컴퓨터의 터미널도 온전히 열 수 있습니다. 터널에만 쓸 수 있는 키를 만들 수 있습니다. 다른 컴퓨터에서 키를 생성하고(`ssh-keygen -t ed25519`), 앱을 실행하는 컴퓨터의 `authorized_keys`에 그 공개 키를 추가하되, 앞에 다음 옵션을 붙이세요.

```
restrict,port-forwarding,permitopen="127.0.0.1:24837",command="exit" ssh-ed25519 AAAA… other-computer
```

`restrict`만으로는 그 키로 여전히 명령을 실행할 수 있습니다. 그 문을 닫는 것은 `command="exit"`이며, 터널은 명령을 요구하지 않습니다. Windows에서 사용자 계정이 관리자라면 이 파일은 `C:\ProgramData\ssh\administrators_authorized_keys`이고, Administrators와 SYSTEM만 쓸 수 있어야 합니다. 관리자가 아니라면 `%USERPROFILE%\.ssh\authorized_keys`입니다. 확인하려면 그 키로 `ssh you@your-computer whoami`를 실행해 보세요. 아무것도 출력하지 않고 바로 끝나야 하며, 그동안 `-N -L` 터널은 계속 작동해야 합니다.

</details>

### Android 앱

Android 10 이상용 앱이 터널을 대신 열고, 내 컴퓨터가 제공하는 같은 인터페이스를 휴대폰 레이아웃으로 보여 줍니다. 백그라운드에서도 연결을 유지하며, 화면이 꺼져 있어도 에이전트가 작업을 마치거나 내 응답을 기다리면 알려 줍니다. 알림을 누르면 그 탭이 열립니다. Wi‑Fi가 다시 연결되면 앱도 스스로 다시 연결합니다.

원격 접속이 켜져 있고 컴퓨터의 SSH 서버가 실행 중이어야 합니다(위의 1, 2단계). [Google Play](https://play.google.com/store/apps/details?id=io.github.cvelasquez.agentworkbench)에서 받거나, [`CONTRIBUTING.md`](CONTRIBUTING.md#the-android-app)의 설명에 따라 [`android/`](android/)에서 직접 빌드하세요.

**페어링(한 번만):**

1. ⇄ 대화 상자에서 **휴대폰 페어링**을 선택합니다. 이 컴퓨터의 터미널에 붙여 넣을 줄과 QR 코드가 나옵니다. Windows에서 사용자 계정이 관리자라면 이 줄은 *관리자 권한으로* 연 PowerShell에 붙여 넣어야 하며, 대화 상자에서도 알려 줍니다.
2. 그 줄을 붙여 넣습니다. 휴대폰의 키를 터널 전용으로 허용하는 줄입니다. 이 키로 휴대폰은 앱에만 접속할 수 있고, 그 밖에는 아무것도 할 수 없습니다. 터미널도, 명령도 안 됩니다.
3. 앱으로 QR 코드를 스캔합니다. 코드는 한 번만, 5분 동안 유효하며, 휴대폰이 연결될 때까지 대화 상자를 열어 두어야 합니다.

QR 코드에는 휴대폰의 SSH 개인 키가 들어 있습니다. 컴퓨터는 휴대폰이 이 키를 사용할 때까지 메모리에만 두고 디스크에는 절대 쓰지 않습니다. **그 QR 코드의 사진을 공유하지 마세요.** 휴대폰은 첫 연결 때 컴퓨터의 SSH 지문을 기억하고, 나중에 지문이 바뀌면 연결을 거부하고 알려 줍니다.

**스크린샷을 에이전트에게 보내세요.** 어떤 앱에서든 **공유 → Agent Workbench**를 누르면 이미지(PNG, JPEG, GIF, WebP)와 텍스트가 컴퓨터의 메모에 저장됩니다. 새 메모나 고른 메모에 넣을 수 있고, 원하면 코멘트도 붙일 수 있습니다. 그다음 메모에서 **입력창으로**를 누르면 고른 대화에 들어갑니다. 휴대폰에는 사본이 남지 않습니다.

**컴퓨터의 IP 주소가 바뀌면** **설정 → 주소 변경**에서 새 주소를 입력하면 되고, 다시 페어링할 필요가 없습니다. 앱은 그 주소에서 컴퓨터가 지문과 함께 응답할 때만 저장합니다.

**휴대폰을 제거하려면** 대화 상자에서 **권한 취소**를 누르고, `authorized_keys`에서 그 휴대폰의 줄(`agent-workbench-phone`으로 끝남)을 지우세요. 휴대폰에서는 **설정 → 이 컴퓨터 삭제**를 누르면 키와 자격 증명이 삭제됩니다.

휴대폰이 대기 상태일 때 알림이 늦게 온다면 앱이 배터리 제한 없이 실행되도록 하세요. **설정 → 앱의 배터리 설정 열기**에서 바꿀 수 있습니다. 앱이 휴대폰에 저장하는 내용과 요청하는 권한은 [`PRIVACY.md`](PRIVACY.md)에 있습니다.

## 데이터와 보안

- **Agent Workbench는 어디로도 아무것도 보내지 않습니다.** 텔레메트리도, 분석도, 앱 자체의 네트워크 요청도 없습니다. Android 앱은 내 컴퓨터와만 통신합니다.
- **각 CLI는 직접 실행했을 때 하던 일을 여전히 스스로 합니다.** AI 제공업체와 통신하고, 업데이트를 확인하거나 자체 사용 데이터를 보낼 수도 있습니다. Agent Workbench는 여기에 아무것도 더하지 않고, 끄지도 않습니다. 어떤 CLI의 설정도 바꾸지 않기 때문입니다. 각 CLI가 무엇을 보내는지는 그 CLI의 문서에 있습니다.
- **자격 증명에는 절대 손대지 않습니다.** 로그인 화면이 없습니다. CLI가 로그인을 요구하면 그 CLI의 터미널에서 직접 로그인하며, 앱은 그 사실조차 알지 못합니다.
- **CLI의 기록을 읽지만 CLI 폴더에는 아무것도 쓰지 않습니다.** 무엇을 읽고 무엇을 절대 열지 않는지는 아래 표에 있습니다.
- **앱 자체 폴더에만 씁니다.** 예외는 프로젝트 안의 세 가지뿐입니다. 확인한 경우의 공유 메모리, 파일 탭에서 직접 편집하고 저장한 파일, 그리고 직접 연 별도 브랜치입니다. 별도 브랜치는 각각 프로젝트 옆의 자기 폴더에 있고, 제거하거나 통합할 때 브랜치에서 바뀐 메모는 메인 폴더로 돌아갑니다.
- **서버는 내 컴퓨터(`127.0.0.1`)에서만 연결을 받습니다.** 포트는 무작위이고 실행할 때마다 새 무작위 토큰을 쓰며, 다른 웹 페이지에서 온 요청은 거부합니다. 원격 접속을 켜도 이 점은 같습니다. 포트가 고정될 뿐 여전히 `127.0.0.1`에 있고, 나머지는 사용자가 직접 켜고 관리하는 SSH가 맡습니다.
- **Git: 앱은 커밋도 푸시도 하지 않고, 히스토리를 다시 쓰지도 않습니다.** 무언가를 쓰는 git 명령은 네 가지뿐이고, 각각 그 명령을 보여 주는 확인 뒤에 실행합니다. 브랜치를 자기 폴더에 여는 `git worktree add`, `git worktree remove`(`--force`는 절대 쓰지 않음), `git branch -d`(앱이 만들었고 이미 통합된 브랜치만), 그리고 커밋을 만들지 않고 브랜치를 main에 통합하는 `git merge --ff-only`입니다. 브랜치를 제거할 때 앱이 직접 파일을 지우는 경우는 두 가지뿐입니다. 대화 상자에 나열된 새 파일을 잃기로 선택했을 때 그 파일들, 그리고 git이 브랜치 폴더를 끝까지 지우지 못했을 때 남은 것입니다. 커밋은 에이전트가 자기 터미널에서 합니다.

**알아 둘 만한 흔적 세 가지:**

- **OpenCode 데이터베이스를 읽으면** SQLite가 모든 읽기 작업에서 하는 일이 그대로 일어납니다. `-wal`과 `-shm` 파일이 없으면 만들고, `-shm`의 날짜를 갱신합니다. 앱은 데이터베이스를 읽으려고 OpenCode 명령을 실행하지 않습니다.
- **Antigravity 탭 자체의 로그가 나타나지 않으면** 앱은 CLI의 `log/cli-*.log` 파일을 읽습니다. 이 파일에는 내 메시지와 계정 이메일이 들어 있지만, 대화 ID를 찾는 데만 쓰고 어떤 줄도 보관하지 않습니다.
- **OpenCode를 쓰면 앱이 로컬 OpenCode 서버를 실행합니다**(`opencode serve`). 서버는 하나뿐이며, 첫 OpenCode 탭을 열 때부터 마지막 탭을 닫고 5분이 지날 때까지, 또는 앱을 닫을 때까지 실행됩니다. OpenCode 설정이 다르게 되어 있어도 `127.0.0.1`의 무작위 포트에서, 실행할 때마다 다른 비밀번호로 연결을 받습니다. 앱이 이 서버에 요청하는 것은 세션 상태, 대기 중인 권한 요청과 질문, 세션 생성, 질문에 대한 답변, 세션 중지뿐이며, 설정이나 계정에 관한 것은 묻지 않습니다.

**환경 변수.** CLI는 사용자의 환경을 그대로 물려받으며, 로그인 변수는 하나도 추가되지 않습니다. 예외는 두 가지입니다. 앱은 기록 저장을 끄는 `CLAUDE_CODE_CHILD_SESSION`을 **제거**하고, 제거할 때 배너로 알려 줍니다. 그리고 OpenCode 서버에는 실행할 때마다 바뀌는 그 비밀번호를 담은 변수 `OPENCODE_SERVER_PASSWORD` 하나를 **추가**합니다. 이 비밀번호는 어떤 계정의 비밀번호도 아니며, 이 변수는 어떤 탭에도 들어가지 않습니다. 각 OpenCode 탭은 명령줄(`attach --password`)로 비밀번호를 받는데, 같은 사용자로 실행 중인 다른 프로그램은 그곳에서 비밀번호를 볼 수 있습니다. 이 비밀번호는 그 서버에만 쓸 수 있고, 앱을 닫으면 더 이상 쓸 수 없습니다.

**Pi가 스스로 보내는 것.** Pi는 시작할 때 pi.dev에서 최신 버전과 모델 카탈로그를 확인하고, 설치하거나 업데이트할 때마다 그곳에 보고합니다. 이 보고는 여기가 아니라 Pi에서 끕니다. Pi 설정의 `enableInstallTelemetry: false`나 환경 변수 `PI_TELEMETRY=0`을 쓰면 됩니다.

**앱이 쓰는 것:**

- **앱 자체 설정 폴더:** 열린 탭, 인덱스 캐시, 메모, 보관된 세션, 보내지 않은 메시지와 예약 메시지, Claude Code와 Antigravity의 상태 표시줄 스크립트와 그 스크립트가 저장하는 내용, 앱이 만든 별도 브랜치의 목록과 그 브랜치에 복사한 각 텍스트 메모의 사본(나중에 메모를 합치기 위한 것), 그리고 켰다면 백업(또는 직접 고른 폴더에). 원격 접속을 켜면 페어링된 기기 목록도 씁니다. 기기마다 이름, 날짜 두 개, 자격 증명의 해시를 쓰며, 자격 증명 자체는 절대 쓰지 않습니다.
- **임시 폴더:** 붙여 넣거나 첨부한 이미지와 파일, 각 Antigravity 탭의 로그(내 메시지가 들어 있으며, 본인만 읽을 수 있고, 24시간이 지난 뒤 처음 시작할 때 삭제됨), 다른 CLI로 이어 가는 대화의 트랜스크립트(그 탭을 닫거나 24시간이 지나면 삭제됨). 별도 브랜치가 충돌할지 확인할 때는 git이 객체를 저장소가 아니라 임시 폴더에 쓰며, 그 폴더는 바로 삭제됩니다.
- **프로젝트에는 세 가지만:** 확인한 경우의 공유 메모리. `.agents/memory/`, `AGENTS.md`와 `CLAUDE.md`의 마커 사이 내용, `.gitignore` 끝의 몇 줄로 한정됩니다. 파일 탭에서 편집한 파일을 저장할 때입니다. 이미 있는 파일의 내용만 바꾸며, 아무것도 만들거나 이름을 바꾸거나 지우지 않고, CLI 폴더 안에는 아무것도 쓰지 않습니다. 그리고 별도 브랜치의 메모입니다. 브랜치를 제거하거나 통합할 때 메인 폴더로 돌아갑니다. 메모가 양쪽에서 바뀌었다면 git이 코드를 합치는 방식으로 두 버전을 합치며, 양쪽이 같은 줄을 바꾼 곳만 직접 고릅니다.

## 문제 해결

**"PATH에서 "claude" 명령을 찾을 수 없습니다"에 이어 "다음 CLI에서도 사용할 수 있습니다: …"가 표시됩니다.** 앱이 CLI를 하나도 찾지 못한 것입니다. Windows에서는 `where claude`(다른 OS에서는 `which claude`)로 확인하고, `codex`, `opencode`, `agy`, `pi`도 같은 방법으로 확인하세요. CLI는 앱이 시작할 때 찾으므로, 앱이 열려 있는 동안 CLI를 설치했다면 앱을 다시 시작하세요.

**Pi가 설치되어 있는데 앱이 찾지 못합니다.** 앱은 Pi를 찾으려고 `pi`를 실행하지 않고, 명령 옆에 있는 Pi 패키지에서 버전을 읽습니다. npm이나 pi.dev 설치 프로그램으로 Pi를 설치했다면 이 방식이 통하지만, 단독 실행형 `pi` 바이너리는 인식하지 못합니다. 그리고 `PATH`에서 `pi`라는 다른 프로그램이 먼저 나오면 앱은 그것을 무시하고 자체 콘솔에 그렇다고 알려 줍니다.

**Pi 탭의 입력창에 "CLI가 응답을 기다리고 있습니다"라고 나옵니다.** Pi가 프로젝트 폴더를 신뢰할지 묻고 있는 것입니다. **CLI** 탭에서 답하세요. 앱은 이 질문에 절대 대신 답하지 않습니다.

**OpenCode 기록이 나타나지 않습니다.** 앱이 시작할 때 나오는 `History` 줄을 보세요. 그 Node 버전에 `node:sqlite`가 없다고 나오면 Node를 22.13 이상으로 업데이트하세요. 그런 줄이 없다면 데이터베이스를 찾지 못한 것입니다. 데이터베이스는 `~/.local/share/opencode/opencode.db`에 있거나, `OPENCODE_DB` 또는 `XDG_DATA_HOME`이 가리키는 곳에 있습니다.

**OpenCode 탭이 열리지 않고 "Couldn't start the OpenCode server"라고 나옵니다.** 원인은 콜론 뒤에 나옵니다. 원인이 분명하지 않으면 일반 터미널에서 `opencode`를 실행해 보세요. 거기서도 시작되지 않는다면 그 OpenCode 설치 자체에 문제가 있는 것입니다.

**OpenCode 탭에 서버가 종료되었다고 나옵니다.** 같은 알림 바의 **다시 실행**을 누르면 서버를 새로 시작하고 탭을 같은 세션에 다시 연결합니다.

**Claude Code의 요금제 사용 한도가 표시되지 않습니다.** 미터에 **설정** 버튼이 나오면 [이 단계](#claude-code-요금제-사용-한도)를 따르세요. **데이터 없음**이라고 나오면 상태 표시줄은 설정되었지만 아직 한도를 제공하지 않은 것입니다. 한도는 각 세션의 첫 응답과 함께 들어오며, 구독 요금제에서만 제공됩니다.

**Antigravity 탭에 상태나 미터가 표시되지 않습니다.** 앱이 시작할 때 CLI 아래에 나오는 `Status line` 항목을 보세요. 설정되지 않았다거나 다른 상태 표시줄이 있다고 나오면 [이 단계](#antigravity-cli-상태와-컨텍스트-미터)를 따르세요. 설정했는데도 CLI 터미널에 `Statusline Error`가 표시된다면 그 세션의 `PATH`에 `node`가 없을 가능성이 큽니다.

**설치할 때 `node-pty`가 컴파일되지 않습니다.** 터미널의 네이티브 모듈입니다. 보통은 미리 빌드된 바이너리를 내려받지만, 사용하는 Node와 플랫폼에 맞는 바이너리가 없으면 컴파일해야 합니다.

- **Windows:** *C++를 사용한 데스크톱 개발* 워크로드가 포함된 Visual Studio Build Tools와 Python 3. (npm의 `windows-build-tools`는 더 이상 유지 관리되지 않습니다.)
- **macOS:** `xcode-select --install`.
- **Linux:** `build-essential`과 `python3`.

**터미널이 빈 화면으로 남습니다.** 기본 렌더러는 일부러 canvas로 되어 있습니다. WebGL을 쓰면 Windows 11 + Chrome에서 탭이 멈추기 때문입니다. 그래도 WebGL을 써 보려면 주소에 `?renderer=webgl`을 추가하세요.

**`CLAUDE_CODE_CHILD_SESSION`을 제거했다는 배너가 나옵니다.** Claude Code 세션 안에서 앱을 시작했기 때문입니다. 이 변수는 기록 저장을 끄기 때문에 앱이 이를 제거하고 알려 줍니다. 일반 터미널에서 시작하면 이 배너는 볼 일이 없습니다.

**다른 컴퓨터에서 `ssh`로 연결되지 않습니다**(시간 초과 또는 거부). 앱이 있는 컴퓨터에서 SSH 서버가 실행 중이지 않거나, 두 컴퓨터 사이의 무언가가 연결을 막고 있습니다. Windows에서는 Wi‑Fi 네트워크가 *개인*으로 설정되어 있는지 확인하세요. SSH 서버의 방화벽 규칙이 *공용* 네트워크에는 적용되지 않을 수 있습니다. 로컬 네트워크를 막는 회사 VPN도 연결되어 있는 동안에는 접속을 끊습니다. `ssh`가 사용자를 거부한다면, Microsoft 계정이나 회사 계정은 PIN이 아니라 사용자 폴더 이름(`C:\Users\<name>`)과 계정 비밀번호가 필요할 수 있습니다.

**다른 컴퓨터에서 페이지에 "Origin not allowed"라고 나옵니다**(403). 컴퓨터 이름이나 IP 주소로 열었기 때문입니다. 터널의 양쪽 끝에서 같은 포트를 쓰는 상태로 `http://localhost:<port>`를 여세요.

**다른 컴퓨터에서 페이지에 세션 토큰이 없다고 나옵니다**(401). 그 브라우저가 페어링되지 않았거나, 권한이 취소되었거나, 원격 접속이 꺼져 있습니다. ⇄ 대화 상자에서 다시 페어링하세요.

**⇄ 대화 상자에 포트가 사용 중이라고 나옵니다.** 다른 프로그램(대개 두 번째로 실행한 Agent Workbench)이 그 포트를 쓰고 있습니다. 그 프로그램을 닫고 다시 시작하거나 다른 포트를 고르세요.

**변경 사항 패널에 폴더가 git 저장소가 아니라고 나오는데**, 실제로는 저장소입니다. `git`이 `PATH`에 있는지 확인하세요. 다른 메시지가 나온다면 git 자체의 오류를 그대로 보여 주는 것입니다.

## 소스에서 실행

앱을 개발하거나, 전역으로 아무것도 설치하고 싶지 않다면:

```bash
corepack enable pnpm
pnpm install
pnpm dev       # 핫 리로드 사용
```

```bash
pnpm build     # 인터페이스를 한 번 빌드
pnpm start     # 빌드된 인터페이스 제공
```

**Windows에서 클릭 한 번으로 시작하기:** `pnpm package`를 실행하면 인터페이스를 빌드하고 루트에 **`Agent Workbench.cmd`** 파일을 남깁니다. 이 파일을 더블클릭하면 빠진 것을 설치하고, 필요하면 빌드한 뒤 브라우저를 엽니다. 실행하기 전에 읽어 볼 수 있는 20줄짜리 텍스트 파일입니다.

## 내부 구조

pnpm 모노레포이며, 전체가 TypeScript로 작성되어 있습니다.

```
packages/
  server/    Node, Express, ws, node-pty, chokidar — serves the interface and runs the terminals
    src/agents/   one adapter per CLI: the only part of the server that knows each one
  web/       Vite, React, xterm.js, highlight.js
  shared/    the protocol types, with no `any` at the edges
android/     the Android app, in Kotlin: the SSH tunnel, the interface, the notifications
```

나머지 설계는 두 가지 결정에서 나옵니다. **터미널은 서버에 있고, 브라우저는 그 터미널을 보여 주는 창일 뿐입니다.** 그래서 페이지를 닫거나 새로 고쳐도 작업 중인 세션은 끝나지 않습니다. 그리고 **범용 서버는 어떤 CLI도 이름으로 언급하지 않습니다.** 각 CLI에 대해 아는 것(어디에 무엇을 두는지, 어떻게 실행하는지, 무엇을 읽고 무엇을 절대 열지 않는지)은 그 CLI의 어댑터에 있고, 인터페이스는 각 CLI가 선언한 내용에 따라 컨트롤을 표시합니다.

[`ARCHITECTURE.md`](ARCHITECTURE.md)에는 반드시 지켜야 할 규칙과 코드 지도가, [`CONTRIBUTING.md`](CONTRIBUTING.md)에는 저장소에서 작업하는 방법이, [`SECURITY.md`](SECURITY.md)에는 취약점 신고 방법이, [`PRIVACY.md`](PRIVACY.md)에는 수집하는 정보(없음)가, [`CHANGELOG.md`](CHANGELOG.md)에는 버전별 변경 사항이 있습니다(모두 영문). 코드 주석은 스페인어로 되어 있습니다. 이 README의 스크린샷은 가상의 데이터로 `pnpm demo:shots`를 실행해 만든 것입니다.
