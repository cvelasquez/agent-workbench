**Визуальная рабочая среда для агентов программирования, которыми вы уже
пользуетесь: CLI Claude Code, Codex, OpenCode, Antigravity и Pi.** Работает на вашем
компьютере и открывается в браузере. Использует уже установленные у вас CLI, в
которых вы вошли в аккаунт, никогда не трогает ваши учётные данные и не делает
собственных сетевых запросов.

```bash
npx agent-workbench
```

![Обзор: диалог в виде карточек, изменённые файлы и diff, по вкладке на каждый CLI и продолжение диалога в другом CLI](assets/demo.webp)

## Как это работает

Agent Workbench не обращается ни к какому ИИ-сервису. Он запускает CLI, который у
вас уже есть, — `claude`, `codex`, `opencode`, `agy` или `pi` — в настоящем терминале
и добавляет вокруг то, чего терминал сам по себе не даёт: вкладки, ваши прошлые
диалоги, диалог в виде удобных для чтения карточек, индикатор контекста,
изменённые файлы и дерево файлов.

Терминал остаётся терминалом: всё, что вы вводите, уходит прямо в CLI.

## Возможности

| | |
|---|---|
| **Вкладки** | Несколько агентов одновременно, из любого CLI, каждый в своей папке. Точка на каждой вкладке показывает, работает ли агент, свободен или ждёт вас. Перезагрузка страницы ничего не останавливает: CLI работают на сервере, а не в браузере. |
| **Быстрый запуск** | Когда вы открываете приложение, вкладки возвращаются **спящими**: их можно читать целиком, и ни один CLI не запускается, пока вы не нажмёте **Открыть CLI**. |
| **История** | Ваши проекты и прошлые диалоги на боковой панели, из всех CLI, с фильтром. Нажмите на диалог, чтобы продолжить его с того места, где вы остановились, в его же CLI. Старые сессии или целый проект можно архивировать, чтобы навести порядок: ничего не удаляется, и это можно отменить. |
| **Диалог** | Сообщения в виде карточек, в реальном времени, со свёрнутыми вызовами инструментов. Более ранние сообщения подгружаются при прокрутке вверх. Можно искать, копировать любое сообщение или блок кода, возвращаться к своему предыдущему сообщению (↑) и переходить в конец (↓). Строка внизу показывает, когда ваше сообщение дошло до CLI и работает ли ещё агент. В зависимости от CLI на вопросы агента можно отвечать прямо здесь. |
| **Поле ввода** | Место, чтобы писать, вставлять изображения и прикреплять файлы; длинный вставленный текст сворачивается в аккуратную плашку. Набранный текст не пропадает при закрытии приложения и в реальном времени появляется во всех открытых окнах. |
| **Индикатор контекста** | Какую часть окна контекста модели занимает диалог. Только токены — никогда не деньги. |
| **Изменения** | Ветка, изменённые файлы и их diff. **Только чтение**: никаких кнопок commit или push. |
| **Файлы** | Дерево файлов проекта с поиском и предпросмотром с подсветкой синтаксиса. Можно открыть несколько файлов сразу, каждый в своей вкладке; файлы Markdown открываются отформатированными. Одно нажатие вставляет путь к файлу в ваше сообщение. |
| **Планы** | Планы и документы `.md`, созданные в диалоге, в отформатированном виде. |
| **Заметки** | Блокнот рядом с диалогом, в том числе с изображениями. С Claude Code заметку можно одним нажатием отправить в новый диалог. |
| **Консоль** | Системный терминал внизу, в папке проекта: PowerShell, cmd или Git Bash в Windows; bash или zsh в macOS и Linux. |
| **Продолжить в…** | Если CLI больше одного, диалог можно продолжить в другом CLI в той же папке. Новый агент начинает с транскрипта последних ходов. |
| **Уведомления** | Звук и, по желанию, системные уведомления, когда агент закончил работу или ждёт вас. |
| **Настройки** | ⚙ в верхней панели: язык, тема терминала, какие панели показывать, какая консоль открывается и какие CLI использует приложение. |
| **Девять языков** | English, Español, 简体中文, 日本語, Português (Brasil), Русский, 한국어, Français и Deutsch. Язык выбирается по браузеру. |
| **Тема** | Светлая, тёмная или системная. Терминал по умолчанию остаётся тёмным, чтобы цвета CLI хорошо читались. |

### Если CLI больше одного

У каждой сессии и каждой вкладки есть маленький значок её CLI, а кнопка `+` для
новой вкладки позволяет выбрать, какой из них открыть. Если CLI один, ничего
этого не видно.

<img src="assets/captura-clis.png" width="45%" alt="Боковая панель проектов с сессиями нескольких CLI, у каждой свой значок, и меню + с пятью CLI и их версиями">

**Не все CLI сообщают одни и те же данные**, поэтому некоторые функции зависят
от CLI:

| | Claude Code | Codex | OpenCode | Antigravity CLI | Pi |
|---|:---:|:---:|:---:|:---:|:---:|
| Точка на вкладке: работает, свободен, ждёт вас | ✓ | — | ✓ ¹ | ✓ ² | ✓ |
| Ответы на вопросы агента прямо из диалога | ✓ | — | ✓ ¹ | — | — |
| Индикатор контекста | ✓ | ✓ | ✓ | ✓ ² | ✓ |
| Выбор режима и модели | ✓ | — | — | ✓ | ✓ ³ |
| Вставка изображений | ✓ | ✓ | ✓ | — | ✓ ³ |
| Вкладка «Планы» | ✓ | — | — | — | — |
| Отправка заметки в новый диалог | ✓ | — | — | — | — |

Для всего остального всегда есть собственный терминал CLI: например, там, где
стоит «—», на вопросы отвечают в нём.

¹ Чтобы получить эти данные от OpenCode, приложение запускает его локальный
сервер ([подробнее](#ваши-данные-и-безопасность)).
² Только если настроить его строку состояния
([как это сделать](#antigravity-cli-статус-и-индикатор-контекста)).
³ У Pi нет режимов разрешений: у него выбираются модель и уровень размышления.
И вставленное он не прикрепляет: изображение передаётся как путь к файлу,
который модель открывает сама.

## Требования

- **Node.js 20 или новее.** Чтобы видеть историю OpenCode и названия диалогов
  Antigravity CLI, нужна версия **22.13 или новее**: они читаются через SQLite,
  встроенный в Node начиная с этой версии. Со старой версией работает всё
  остальное.
- **git** — для панели «Изменения». Всё остальное работает и без него.
- **Хотя бы один CLI**, установленный и с выполненным входом в аккаунт:

| CLI | Команда | Как установить |
|---|---|---|
| Claude Code | `claude` | [руководство по установке](https://docs.claude.com/en/docs/claude-code/setup) |
| Codex | `codex` | [руководство](https://learn.chatgpt.com/docs/codex/cli) |
| OpenCode | `opencode` | [документация](https://opencode.ai/docs/) |
| Antigravity CLI | `agy` | [руководство](https://antigravity.google/docs/cli/getting-started) |
| Pi | `pi` | [pi.dev](https://pi.dev) |

Agent Workbench не включает в себя и не скачивает ни один CLI: он находит те,
что есть в вашем `PATH`. Если их нет, он сообщает об этом и не открывает сессии.

**Платформы.** Разрабатывается и каждый день используется в Windows 11 с
PowerShell. В macOS и Linux установка и запуск автоматически проверяются при
каждом изменении, но в повседневной работе эти системы используются реже:
сообщения о проблемах приветствуются. В Linux при установке компилируется
модуль терминала, поэтому нужны `python3`, `make` и компилятор C++
(`build-essential` в Debian и Ubuntu).

## Установка и запуск

```bash
npm install -g agent-workbench
```

Затем из папки проекта, над которым хотите работать:

```bash
agent-workbench
```

Приложение откроет браузер по адресу примерно такого вида:

```
  URL          http://127.0.0.1:52341/?token=…
```

Попасть в приложение можно только по этому адресу: токен меняется при каждом
запуске, а подключения принимаются только на вашем собственном компьютере
(`127.0.0.1`).

Чтобы один раз попробовать без установки: `npx agent-workbench`. В первый раз
скачивается около 60 МБ, в основном нативный модуль терминала. Для
повседневной работы лучше глобальная установка.

## Сочетания клавиш

| Клавиши | Действие |
|---|---|
| `Alt+T` | Новая вкладка |
| `Alt+W` | Закрыть вкладку |
| `Alt+←` / `Alt+→` (или `Alt+PgUp` / `Alt+PgDn`) | Предыдущая / следующая вкладка |
| `Alt+P` | Показать или скрыть правую панель |
| `Shift+Tab` вне терминала | Вернуться к предыдущей вкладке |

Кнопка `?` в верхней панели показывает их все вместе с собственными
сочетаниями активного CLI. Они построены на `Alt`, потому что `Ctrl+T`,
`Ctrl+W` и `Ctrl+Tab` браузер оставляет для своих вкладок и никогда не передаёт
странице.

Все остальные клавиши — `Esc`, `Ctrl+C`, `Ctrl+R`, `Ctrl+O`, стрелки, `Alt+V`
для вставки изображений — доходят до CLI без изменений. `Ctrl+V` тоже: что при
этом произойдёт, решает CLI. Только в консоли внизу, в Windows, `Ctrl+V`
вставляет текст, как в Windows Terminal.

## Дополнительные возможности

### Общая память для всех CLI

Каждый CLI хранит то, что узнал о проекте, у себя, и остальные этого не видят.
Вкладка **Память** настраивает одну память на всех: заметки в папке
проекта `.agents/memory/`, которые каждый CLI читает и записывает — отсюда или
из своего терминала — через `AGENTS.md` и `CLAUDE.md`. Поначалу вкладка скрыта:
включите её в ⚙ Настройках.

Кнопка **Просмотреть изменения** показывает, файл за файлом, что будет
записано, и ничего не меняется, пока вы не подтвердите. При настройке
импортируется память, которая уже была у Claude Code для этого проекта.
Глобальные настройки каждого CLI приложение не редактирует: оно даёт вам
фрагмент, который вы вставляете сами.

<img src="assets/captura-memoria.png" width="70%" alt="Вкладка «Память» с мостом, установленным для пяти CLI, и импортированными заметками">

### Резервная копия истории

Историей распоряжается сам CLI: он может сменить её формат, подчистить её или
вовсе быть удалён. Резервная копия сохраняет ваши диалоги —
сообщения, вызовы инструментов и их результаты, изображения и память каждого
проекта — в вашей папке, в файлах, которые можно читать без приложения.

**По умолчанию она выключена.** Откройте её кнопкой резервной копии вверху
боковой панели проектов или из ⚙ Настроек. Кнопка **Подсчитать** показывает,
сколько места она займёт для каждого CLI, ничего не записывая, а **Включить**
её запускает. С этого момента она копирует всё, что есть на боковой панели и
не архивировано, а диалог копирует заново через минуту после того, как он
перестал меняться. Из этой папки она никогда ничего не удаляет.

Когда резервная копия включена:

- Диалоги, которых в CLI больше нет, остаются на боковой панели с пометкой
  «копия» и открываются как Markdown.
- Любой проект можно экспортировать в Markdown.
- Если CLI больше одного, фильтр боковой панели может искать **В диалогах**:
  по тексту всего скопированного, из всех CLI.

<img src="assets/captura-buscador.png" width="40%" alt="Поиск по диалогам: совпадение в одной сессии каждого CLI с фрагментом текста">

По умолчанию она хранится в папке конфигурации приложения
(`%APPDATA%\agent-workbench\vault` в Windows). **Сменить папку…** копирует её в
другую папку — синхронизируемую или на другом диске, — ничего не
перезаписывая, а прежнюю оставляет нетронутой. Если поместить её в
синхронизируемую папку или в репозиторий, ваши диалоги окажутся там вместе с
ней.

<details>
<summary>Импорт истории из Gemini CLI и Antigravity IDE</summary>

Два одноразовых импортёра переносят историю из инструментов, которые
приложение не читает. Они запускаются из исходного кода
([см. ниже](#запуск-из-исходного-кода)) и **ничего не записывают без
`--write`**: без этого флага они только сообщают, что импортировали бы.

- `pnpm vault:import gemini-cli [--cwd <folder>]` — чаты, оставшиеся от
  Gemini CLI. `--cwd` — папка, в которой вы им пользовались, чтобы отнести их
  к этому проекту.
- `pnpm vault:import antigravity-ide --workspace <folder>` — то, что удаётся
  прочитать из диалогов Antigravity IDE в этой папке: сводку каждого и его
  документы `.md`. Сам диалог зашифрован, поэтому он помечается как частичная
  история.

</details>

### Antigravity CLI: статус и индикатор контекста

Antigravity CLI сообщает, работает ли он или ждёт вас и сколько токенов
израсходовал, только через свою *строку состояния*. Без неё его вкладки
работают как обычно, но точка на вкладке показывает, что статус неизвестен, а
индикатор остаётся пустым. Чтобы её включить:

1. Откройте вкладку Antigravity и нажмите **Настроить** рядом с индикатором.
2. Скопируйте показанную строку и добавьте её к тому, что уже есть в
   `~/.gemini/antigravity-cli/settings.json`. Приложение этот файл не
   редактирует — это делаете вы.
3. Через пару секунд или после нажатия **Проверить** окно покажет
   **Настроена**.

Эта строка запускает небольшой скрипт, который хранится в собственной папке
приложения. Он сохраняет только статус, режим, модель и токены каждого
диалога — не ваш email, квоту, тариф или стоимость, которые CLI ему тоже
передаёт, — и ничего не выводит, так что собственная строка состояния CLI
остаётся прежней. После настройки он выполняется в **каждой** сессии `agy`,
включая открытые вне приложения, и ему нужен `node` в `PATH`.

### Удалённый доступ через SSH

Оставьте Agent Workbench работать на одном компьютере и пользуйтесь им с
другого компьютера в вашей сети, в его браузере, без установленных там CLI.
**Приложение никогда не открывается в сеть**: оно по-прежнему принимает
подключения только на `127.0.0.1`, а другой компьютер подключается к нему
через SSH-туннель. Туннель же и делает всё это возможным: через него другой
браузер видит приложение как `localhost`, а браузеры требуют этого для работы
с буфером обмена и уведомлениями. **По умолчанию удалённый доступ выключен.**

**1. На компьютере, где работает приложение, один раз: включите SSH-сервер.**
Это системное изменение, для него нужны права администратора, поэтому
приложение не делает этого за вас.

- **Windows 10/11** — в PowerShell *от имени администратора*. Первая строка
  скачивает и устанавливает сервер и занимает несколько минут: дождитесь, пока
  снова появится приглашение командной строки.

  ```powershell
  Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
  Start-Service sshd
  Set-Service -Name sshd -StartupType Automatic
  ```

- **macOS** — Системные настройки → Основные → Общий доступ → **Удалённый вход**.
- **Linux** — установите и включите сервер OpenSSH вашего дистрибутива. В
  Debian или Ubuntu:

  ```bash
  sudo apt install openssh-server
  sudo systemctl enable --now ssh
  ```

**2. В приложении: ⇄ в верхней панели → «Включить удалённый доступ», затем
перезапустите Agent Workbench.** Туннелю нужен порт, который не меняется,
поэтому приложение использует фиксированный (по умолчанию 24837, его можно
сменить), а порт выбирается при запуске. Перезапуск закрывает открытые CLI;
вкладки вернутся спящими. *Выключение* действует сразу.

**3. На другом компьютере, каждый раз: откройте туннель.** Окно показывает
готовую к копированию команду:

```
ssh -N -L 24837:127.0.0.1:24837 you@your-computer
```

Оставьте её работать и **используйте один и тот же порт на обоих концах**: с
другим локальным портом приложение отвечает 403. Если добавить
`-o ServerAliveInterval=30 -o ExitOnForwardFailure=yes`, туннель заметит
пропавший Wi‑Fi, а не зависнет. В Windows команду можно сохранить в файл
`.cmd` и запускать двойным щелчком.

**4. Сопряжение этого компьютера, один раз.** В окне кнопка **Сопрячь устройство**
даёт адрес с одноразовым кодом, например
`http://localhost:24837/?pair=K7QM-X2RD`. Откройте его в браузере другого
компьютера в течение пяти минут. После этого тому браузеру достаточно
открывать `http://localhost:24837`, даже после перезапуска приложения. В окне
есть список сопряжённых устройств, а **Отозвать** сразу отключает любое из них.

Сопряжённое устройство может пользоваться всем приложением, кроме управления
удалённым доступом и немногих действий, которые открыли бы окно на компьютере,
где работает приложение, например *Открыть в приложении по умолчанию*. На
таком устройстве в верхней панели виден значок **Удалённо**. Учтите: в
приложении есть консоль и оно запускает агентов, поэтому сопряжённое
устройство может выполнять команды на вашем компьютере — так же, как и вы.
**Сопрягайте только свои устройства.**

**На телефоне или планшете.** Через тот же туннель браузер телефона получает
интерфейс в одну колонку: боковая панель проектов выезжает сбоку, вкладки
находятся в верхней панели, а полоса переключения ведёт к диалогу, CLI,
изменениям, файлам и всему остальному. Такой вид появляется в любом окне
шириной меньше 768 px. На сенсорном экране Enter в поле ввода начинает новую
строку (отправляет сообщение кнопка), а терминал прокручивается, если провести
по нему пальцем.

<details>
<summary>Более безопасный SSH-ключ, который годится только для туннеля (рекомендуется)</summary>

Вход по SSH выполняется под вашим пользователем на том компьютере, поэтому
пароль или ключ, который открывает туннель, открывает там и полноценный
терминал. Можно создать ключ, который годится только для туннеля:
сгенерируйте его на другом компьютере (`ssh-keygen -t ed25519`) и добавьте его
открытую часть в `authorized_keys` на компьютере, где работает приложение,
поставив перед ней такие параметры:

```
restrict,port-forwarding,permitopen="127.0.0.1:24837",command="exit" ssh-ed25519 AAAA… other-computer
```

Один только `restrict` всё ещё позволяет ключу выполнять команды; эту дверь
закрывает именно `command="exit"`, а туннель никогда не запрашивает команду.
В Windows, если ваш пользователь — администратор, этот файл —
`C:\ProgramData\ssh\administrators_authorized_keys`, и права на запись в него
должны быть только у администраторов и SYSTEM; иначе это
`%USERPROFILE%\.ssh\authorized_keys`. Чтобы проверить, выполните
`ssh you@your-computer whoami` с этим ключом: команда ничего не должна вывести
и должна сразу завершиться, а туннель `-N -L` при этом продолжит работать.

</details>

### Приложение для Android

Приложение для Android 10 и новее само открывает туннель и показывает тот же
интерфейс, который отдаёт ваш компьютер, в виде для телефона. Оно остаётся на
связи в фоне и уведомляет вас, когда агент закончил работу или ждёт вас, даже
при выключенном экране; нажатие на уведомление открывает нужную вкладку. Когда
Wi‑Fi возвращается, оно само переподключается.

Для него нужны включённый удалённый доступ и работающий SSH-сервер на
компьютере (шаги 1 и 2 выше). Установите его из
[Google Play](https://play.google.com/store/apps/details?id=io.github.cvelasquez.agentworkbench)
или соберите сами из [`android/`](android/), как описано в
[`CONTRIBUTING.md`](CONTRIBUTING.md#the-android-app).

**Сопряжение, один раз:**

1. В окне ⇄ выберите **Сопрячь телефон**. Появятся строка, которую нужно
   вставить в терминал на этом компьютере, и QR-код. В Windows, если ваш
   пользователь — администратор, строку нужно вставить в PowerShell *от имени
   администратора*; окно об этом подскажет.
2. Вставьте строку. Она разрешает ключ телефона только для туннеля: с ним
   телефон добирается до приложения и больше ни до чего — ни терминала, ни
   команд.
3. Отсканируйте QR-код в приложении. Код одноразовый и действует пять минут, а
   окно должно оставаться открытым, пока телефон не подключится.

В QR-коде находится закрытый SSH-ключ телефона. Компьютер держит его только в
памяти, пока телефон им не воспользуется, и никогда не записывает на диск:
**не делитесь снимком этого QR-кода**. При первом подключении телефон
запоминает SSH-отпечаток вашего компьютера, и если тот когда-нибудь изменится,
телефон откажется подключаться и сообщит вам об этом.

**Чтобы удалить телефон**, нажмите для него **Отозвать** в окне и удалите его
строку из `authorized_keys` (она заканчивается на `agent-workbench-phone`). На
самом телефоне **Настройки → Забыть этот компьютер** удаляет его ключ и учётные
данные.

Если уведомления приходят с опозданием, пока телефон лежит без дела, разрешите
приложению работать без ограничений по батарее:
**Настройки → Открыть настройки батареи приложения**. Что приложение хранит на
телефоне и какие разрешения запрашивает, описано в [`PRIVACY.md`](PRIVACY.md).

## Ваши данные и безопасность

- **Agent Workbench никуда ничего не отправляет.** Ни телеметрии, ни аналитики,
  ни собственных сетевых запросов. Приложение для Android общается только с
  вашим компьютером.
- **Каждый CLI по-прежнему сам делает то же, что делал бы, если бы вы запустили
  его вручную:** общается со своим ИИ-провайдером и может проверять обновления
  или отправлять собственные данные об использовании. Agent Workbench ничего к
  этому не добавляет, но и не отключает этого: он не меняет настройки ни одного
  CLI. Что отправляет каждый CLI, описано в его собственной документации.
- **Приложение никогда не трогает ваши учётные данные.** Экрана входа нет: если
  CLI просит войти, вы делаете это в его собственном терминале, а приложение
  этого даже не замечает.
- **Оно читает историю CLI и ничего не пишет в их папки.** В таблице ниже —
  что оно читает и чего никогда не открывает.
- **Оно записывает только в свои папки**, а в ваших проектах — только одно и
  только с вашего подтверждения: общую память.
- **Сервер принимает подключения только на вашем компьютере** (`127.0.0.1`), на
  случайном порту, с новым случайным токеном при каждом запуске, и отклоняет
  запросы с других веб-страниц. Удалённый доступ этого не меняет: порт
  становится фиксированным, по-прежнему на `127.0.0.1`, а остальное делает
  SSH, который включаете и контролируете вы.
- **Панель «Изменения» только для чтения.** Никаких commit, stage или push:
  когда файлы правит агент, кнопка, которая записывает историю, — это ровно тот
  случай, когда потом никто не знает, кто её нажал.

| CLI | Что читается | Что никогда не открывается |
|---|---|---|
| Claude Code | Из `~/.claude/`: `projects/` (история, а также память каждого проекта — чтобы её импортировать), `sessions/` (ждёт ли CLI вашего ответа) и `plans/`. Для вкладки «Планы» — также файлы `.md`, которые диалог записал в проект или во временную папку этой сессии, — **только те, что названы в диалоге, который вы просматриваете**, без обхода каких-либо папок | `.credentials.json` и любые токены |
| Codex | Из `~/.codex/` (или `CODEX_HOME`): `sessions/` и `archived_sessions/` | `auth.json`, `config.toml` и его базы `*.sqlite` |
| OpenCode | Его база `opencode.db`, открытая только для чтения, и в ней только сессии, сообщения и части; а также его каталог моделей — для размера окна контекста | `auth.json`, `opencode.json` и таблицы учётных записей, учётных данных, разрешений и общих сессий |
| Antigravity CLI | Из `~/.gemini/antigravity-cli/`: транскрипты каждого диалога, `history.jsonl`, последний диалог каждой папки, модель и строка состояния из `settings.json` и временная **копия** его индекса диалогов; из `~/.gemini/config/projects/` — папка каждого проекта | Его конфигурация MCP, его запись в системном хранилище ключей, содержимое `conversations/` и `~/.gemini/antigravity/` — это его IDE |
| Pi | Из `~/.pi/agent/` (или `PI_CODING_AGENT_DIR`): сессии в `sessions/` и `models-store.json`, его каталог моделей, — для размера окна контекста и выбора модели. Из установленного пакета Pi: его `package.json` — чтобы узнать версию, не запуская Pi, — и его встроенный список моделей | `auth.json`, `models.json`, `settings.json` и его конфигурация MCP |

[Импортёры резервной копии](#резервная-копия-истории), если вы их запускаете,
читают ещё и то, что указано в их разделе. Полный список, файл за файлом, — в
[`ARCHITECTURE.md`](ARCHITECTURE.md#4-what-is-read-from-each-cli).

<details>
<summary>Мелким шрифтом: следы, переменные окружения и что записывает приложение</summary>

**Три следа, о которых стоит знать:**

- **Чтение базы OpenCode** делает то же, что SQLite делает при любом чтении:
  создаёт её файлы `-wal` и `-shm`, если их нет, и обновляет дату `-shm`. Чтобы
  её прочитать, приложение никогда не запускает команды OpenCode.
- **Если собственный лог вкладки Antigravity не появляется**, приложение
  читает файлы CLI `log/cli-*.log`, в которых есть ваши сообщения и email
  аккаунта, — только чтобы найти id диалога и не сохраняя ни одной строки.
- **С OpenCode приложение запускает локальный сервер OpenCode**
  (`opencode serve`): всего один, с момента, когда вы открываете первую вкладку
  OpenCode, и до пяти минут после закрытия последней или до закрытия
  приложения. Он принимает подключения на `127.0.0.1`, на случайном порту, с
  новым паролем при каждом запуске, даже если в вашей конфигурации OpenCode
  указано иное. Приложение запрашивает у него только статус сессий, ожидающие
  разрешения и вопросы, а также создаёт через него сессию, отвечает на вопрос
  и останавливает сессию: ничего о вашей конфигурации или учётных записях.

**Переменные окружения.** CLI наследуют ваше окружение как есть, без
добавленных переменных для входа. Два исключения: приложение **удаляет**
`CLAUDE_CODE_CHILD_SESSION` — она отключает сохранение истории — и сообщает об
этом баннером; и **добавляет** одну переменную серверу OpenCode,
`OPENCODE_SERVER_PASSWORD`, с тем самым паролем на текущий запуск. Это не
пароль какой-либо учётной записи, и во вкладки эта переменная не попадает:
каждая вкладка OpenCode получает пароль в своей командной строке
(`attach --password`), где его могут увидеть другие программы, запущенные под
вашим пользователем. Он действует только для этого сервера и перестаёт
работать, когда вы закрываете приложение.

**Что Pi отправляет сам.** При запуске Pi проверяет на pi.dev свою последнюю
версию и каталог моделей и сообщает туда о каждой установке и каждом
обновлении. Эти сообщения отключаются в Pi, а не здесь:
`enableInstallTelemetry: false` в настройках Pi или переменная окружения
`PI_TELEMETRY=0`.

**Что записывает приложение:**

- **В свою папку конфигурации:** открытые вкладки, кэш индекса, заметки,
  архивные сессии, неотправленные сообщения, скрипт строки состояния
  Antigravity и, если вы её включите, резервную копию (или в выбранную вами
  папку). При включённом удалённом доступе — ещё список сопряжённых устройств:
  имя, две даты и хеш учётных данных каждого — но никогда сами учётные данные.
- **Во временную папку:** изображения и файлы, которые вы вставляете или
  прикрепляете; лог каждой вкладки Antigravity — в нём есть ваши сообщения, он
  доступен для чтения только вам и удаляется при первом запуске после того,
  как ему исполнится 24 часа; и транскрипт диалога, который вы продолжаете в
  другом CLI, — он удаляется, когда вы закрываете эту вкладку, или через
  24 часа.
- **В ваши проекты — только одно и только с вашего подтверждения:** общую
  память. Запись ограничена папкой `.agents/memory/`, тем, что находится между
  её метками в `AGENTS.md` и `CLAUDE.md`, и несколькими строками в конце
  `.gitignore`.

</details>

## Решение проблем

**«Команда „claude“ не найдена в PATH», а за ней «Также поддерживаются: …»** —
приложение не нашло ни одного CLI. Проверьте это командой
`where claude` в Windows (`which claude` в других системах), и так же с
`codex`, `opencode`, `agy` или `pi`. CLI ищутся при запуске: если вы установили
один из них, пока приложение было открыто, перезапустите приложение.

**Pi установлен, но приложение его не видит.** Чтобы найти Pi, приложение не
запускает `pi`: оно читает версию из пакета Pi, который лежит рядом с командой.
Это работает, если Pi установлен через npm или установщиком с pi.dev;
отдельный бинарный файл `pi` не распознаётся. А если в вашем `PATH` раньше
стоит другая программа с именем `pi`, приложение её игнорирует и сообщает об
этом в своей консоли.

**На вкладке Pi поле ввода сообщает: «CLI ждёт вашего ответа».** Pi
спрашивает, доверять ли папке проекта. Ответьте на вкладке **CLI**: приложение
никогда не отвечает на этот вопрос за вас.

**История OpenCode не появляется.** Посмотрите на строку `History`, которую
приложение выводит при запуске. Если в ней сказано, что эта версия Node не
включает `node:sqlite`, обновите Node до 22.13 или новее. Если такой строки
нет, база не найдена: она находится в `~/.local/share/opencode/opencode.db`
или там, куда указывает `OPENCODE_DB` или `XDG_DATA_HOME`.

**Вкладка OpenCode не открывается: «Couldn't start the OpenCode server».**
Причина указана после двоеточия. Если она непонятна, запустите `opencode` в
обычном терминале: если и там он не запускается, проблема в самой установке
OpenCode.

**Вкладка OpenCode сообщает, что сервер закрылся.** Кнопка **Перезапустить** на
той же панели запускает новый сервер и снова подключает вкладку к той же
сессии.

**Вкладка Antigravity не показывает статус или индикатор.** Посмотрите на
запись `Status line` под CLI при запуске приложения. Если там сказано, что она
не настроена или что уже есть другая, выполните
[эти шаги](#antigravity-cli-статус-и-индикатор-контекста). Если вы её
настроили, а в терминале CLI видно `Statusline Error`, то, скорее всего,
`node` нет в `PATH` этой сессии.

**`node-pty` не компилируется при установке.** Это нативный модуль терминала.
Обычно он скачивает готовый бинарный файл; если для вашей версии Node и
платформы такого нет, его нужно скомпилировать:

- **Windows:** Visual Studio Build Tools с рабочей нагрузкой
  *Desktop development with C++* («Разработка классических приложений на C++»)
  и Python 3. (`windows-build-tools` из npm больше не поддерживается.)
- **macOS:** `xcode-select --install`.
- **Linux:** `build-essential` и `python3`.

**Терминал остаётся пустым.** По умолчанию используется рендерер canvas, и это
сделано намеренно: с WebGL вкладка зависает в Windows 11 + Chrome. Чтобы всё же
попробовать WebGL, добавьте к адресу `?renderer=webgl`.

**Баннер сообщает, что переменная `CLAUDE_CODE_CHILD_SESSION` удалена.** Вы
запустили приложение изнутри сессии Claude Code. Эта переменная отключает
сохранение истории, поэтому приложение удаляет её и сообщает вам об этом. Из
обычного терминала вы этого никогда не увидите.

**С другого компьютера `ssh` не может подключиться** (истекает время ожидания
или подключение отклонено). На компьютере с приложением не запущен SSH-сервер,
или что-то между двумя компьютерами его блокирует. В Windows проверьте, что
сеть Wi‑Fi отмечена как *частная*: правило брандмауэра для SSH-сервера может
не действовать в *общедоступных* сетях. Рабочий VPN, который блокирует
локальную сеть, тоже обрывает подключение, пока он включён. Если `ssh` не
принимает вашего пользователя, для учётной записи Microsoft или рабочей может
понадобиться имя вашей папки пользователя (`C:\Users\<name>`) и пароль
учётной записи, а не PIN-код.

**С другого компьютера страница пишет «Origin not allowed»** (403). Её открыли
по имени компьютера или IP-адресу. Откройте `http://localhost:<port>`, при этом
туннель должен использовать один и тот же порт на обоих концах.

**С другого компьютера страница сообщает, что нет токена сессии** (401). Этот
браузер не сопряжён, его доступ отозван или удалённый доступ выключен.
Выполните сопряжение заново из окна ⇄.

**Окно ⇄ сообщает, что порт занят.** Его использует другая программа — часто
второй Agent Workbench. Закройте её и перезапустите приложение или выберите
другой порт.

**Панель «Изменения» сообщает, что папка не является репозиторием git**, хотя
это репозиторий. Убедитесь, что `git` есть в `PATH`. Если сообщение другое, это
ошибка самого git, слово в слово.

## Запуск из исходного кода

Чтобы работать над приложением или если вы не хотите ничего устанавливать
глобально:

```bash
corepack enable pnpm
pnpm install
pnpm dev       # с горячей перезагрузкой
```

```bash
pnpm build     # собирает интерфейс один раз
pnpm start     # раздаёт собранный интерфейс
```

**Запуск в один щелчок в Windows:** `pnpm package` собирает интерфейс и кладёт
в корень файл **`Agent Workbench.cmd`**. Запустите его двойным щелчком: он
установит всё недостающее, при необходимости выполнит сборку и откроет браузер.
Это текстовый файл на двадцать строк, который можно прочитать перед запуском.

## Как это устроено

Монорепозиторий на pnpm, везде TypeScript.

```
packages/
  server/    Node, Express, ws, node-pty, chokidar — serves the interface and runs the terminals
    src/agents/   one adapter per CLI: the only part of the server that knows each one
  web/       Vite, React, xterm.js, highlight.js
  shared/    the protocol types, with no `any` at the edges
android/     the Android app, in Kotlin: the SSH tunnel, the interface, the notifications
```

Всё остальное определяют два решения. **Терминалы живут на сервере, а браузер —
лишь окно в них**: закрытие или перезагрузка страницы не убивает работающую
сессию. И **общий код сервера не называет ни одного CLI**: всё, что он знает о
каждом из них, — где тот хранит данные, как запускается, что читается и что
никогда не открывается, — находится в адаптере этого CLI, а интерфейс
показывает каждый элемент управления в зависимости от того, что объявляет этот
CLI.

В [`ARCHITECTURE.md`](ARCHITECTURE.md) — жёсткие правила и карта кода, в
[`CONTRIBUTING.md`](CONTRIBUTING.md) — как работать с репозиторием, в
[`SECURITY.md`](SECURITY.md) — как сообщить об уязвимости, в
[`PRIVACY.md`](PRIVACY.md) — что собирается (ничего), а в
[`CHANGELOG.md`](CHANGELOG.md) — что изменилось в каждой версии (все пять — на
английском). Комментарии в коде — на испанском. Скриншоты в этом README сделаны
командой `pnpm demo:shots` на выдуманных данных.
