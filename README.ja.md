**すでにお使いのコーディングエージェント（Claude Code、Codex、OpenCode、Antigravity、Pi の各 CLI）のための、ビジュアルなワークベンチです**。あなたのコンピューターで動き、ブラウザーで開きます。インストールしてログイン済みの CLI をそのまま使い、認証情報には一切触れず、アプリ自身がネットワーク通信を行うこともありません。

```bash
npx agent-workbench
```

![デモ：カード形式の会話、変更されたファイルと差分、CLI ごとのタブ、別の CLI での会話の続行](assets/demo.webp)

## 仕組み

Agent Workbench は、どの AI サービスとも通信しません。すでにお持ちの CLI（`claude`、`codex`、`opencode`、`agy`、`pi`）を本物のターミナルの中で起動し、その周りに、ターミナルだけでは得られないものを加えます：タブ、過去の会話、読みやすいカード形式の会話、コンテキストメーター、変更されたファイル、ファイルツリー。

ターミナルはターミナルのままです。入力した内容は、すべてそのまま CLI に届きます。

## 主な機能

| | |
|---|---|
| **タブ** | どの CLI でも、複数のエージェントをそれぞれのフォルダーで同時に動かせます。各タブのドットで、エージェントが作業中か、待機中か、あなたの応答を待っているかがわかります。ページを再読み込みしても何も止まりません。CLI はブラウザーではなく、サーバーで動いているからです。 |
| **高速起動** | アプリを開くと、タブは**スリープ中**の状態で戻ります。内容はすべて読めますが、**CLI を起動**をクリックするまで CLI は起動しません。 |
| **履歴** | すべての CLI のプロジェクトと過去の会話がサイドバーに並び、フィルターで絞り込めます。クリックすると、その会話の CLI で、中断したところから再開できます。古いセッションやプロジェクト全体をアーカイブして整理することもできます。何も削除されず、元に戻せます。 |
| **会話** | メッセージをカードとしてリアルタイムに表示し、ツールの呼び出しは折りたたみます。上にスクロールすると、古いメッセージが読み込まれます。検索、メッセージやコードブロックのコピー、自分の前のメッセージ（↑）や末尾（↓）への移動ができます。下部の行で、メッセージが CLI に届いたかどうかと、エージェントがまだ作業中かどうかがわかります。CLI によっては、エージェントの質問にその場で回答できます。エージェントが挙げたプロジェクト内のファイルは、ワンクリックで「ファイル」タブに開けます。 |
| **入力欄** | ゆったり書けるスペースがあり、画像の貼り付けやファイルの添付ができます。長いテキストを貼り付けると、すっきりしたチップにまとまります。入力中の内容はアプリを閉じても消えず、開いているすべてのウィンドウにリアルタイムで表示されます。 |
| **コンテキストメーター** | 会話がモデルのコンテキストウィンドウをどれだけ使っているかを示します。表示するのはトークン数で、金額ではありません。 |
| **変更** | ブランチ、変更されたファイル、その差分。**読み取り専用**で、コミットやプッシュのボタンはありません。 |
| **ファイル** | プロジェクトのファイルツリー。検索と、シンタックスハイライト付きのプレビューがあります。複数のファイルをそれぞれ別のタブで同時に開け、Markdown ファイルは整形して表示されます。ワンクリックで、ファイルのパスをメッセージに入れられます。 |
| **プラン** | 会話が書いたプランや `.md` ドキュメントを、整形して表示します。ワンクリックで、ドキュメントのパスをメッセージに入れられます。 |
| **メモ** | 会話の横に置けるメモ帳で、画像も貼れます。Claude Code なら、ワンクリックでメモを新しい会話に送れます。 |
| **コンソール** | 画面下部に、プロジェクトのフォルダーで開くシステムのターミナルです。Windows では PowerShell、cmd、Git Bash のいずれか、macOS と Linux では bash または zsh です。 |
| **次の CLI で続ける** | 複数の CLI がある場合、会話を同じフォルダーで別の CLI に引き継いで続けられます。新しいエージェントは、直近のターンのトランスクリプトから始めます。 |
| **通知** | エージェントが完了したときや、あなたの応答を待っているときに、通知音で知らせます。システム通知も、オプションで使えます。 |
| **設定** | ヘッダーの ⚙ から、言語、ターミナルのテーマ、表示するパネル、開くコンソール、アプリが使う CLI を選べます。 |
| **9 言語** | English、Español、简体中文、日本語、Português (Brasil)、Русский、한국어、Français、Deutsch。ブラウザーの言語に合わせて表示されます。 |
| **テーマ** | ライト、ダーク、またはシステムの設定に合わせます。CLI の配色が読みやすいように、ターミナルは既定ではダークのままです。 |

### 複数の CLI を使う場合

各セッションと各タブには、その CLI を示す小さなバッジが付きます。新しいタブを開く `+` では、どの CLI で開くかを選べます。CLI が 1 つだけなら、これらは何も表示されません。

<img src="assets/captura-clis.png" width="45%" alt="複数の CLI のセッションがそれぞれバッジ付きで並ぶプロジェクトのサイドバーと、5 つの CLI とそのバージョンが並ぶ + メニュー">

**すべての CLI が同じ情報を公開しているわけではない**ため、一部の機能は CLI によって異なります：

| | Claude Code | Codex | OpenCode | Antigravity CLI | Pi |
|---|:---:|:---:|:---:|:---:|:---:|
| タブのドット：作業中、待機中、あなたの応答待ち | ✓ | — | ✓ ¹ | ✓ ² | ✓ |
| 会話からエージェントの質問に回答 | ✓ | — | ✓ ¹ | — | — |
| コンテキストメーター | ✓ | ✓ | ✓ | ✓ ² | ✓ |
| モードとモデルの選択 | ✓ | — | — | ✓ | ✓ ³ |
| 画像の貼り付け | ✓ | ✓ | ✓ | — | ✓ ³ |
| 「プラン」タブ | ✓ | — | — | — | — |
| メモを新しい会話に送る | ✓ | — | — | — | — |

それ以外のことには、いつでも CLI 自身のターミナルが使えます。たとえば「—」の箇所では、質問にはそのターミナルで回答します。

¹ OpenCode では、これを実現するために、アプリがローカルの OpenCode サーバーを起動します（[詳細](#データとセキュリティ)）。
² ステータスラインを設定した場合のみ（[設定方法](#antigravity-cli状態とコンテキストメーター)）。
³ Pi には権限モードがありません。選択できるのはモデルと思考レベルです。また、貼り付けたものを添付しません。画像はファイルのパスとして送られ、モデルが自分で開きます。

## 必要なもの

- **Node.js 20 以降**。OpenCode の履歴と Antigravity CLI の会話タイトルを表示するには **22.13 以降**が必要です。どちらも、このバージョンから Node に組み込まれている SQLite で読み取るためです。それより古いバージョンでも、ほかの機能はすべて動きます。
- **git**：「変更」パネルに必要です。ほかの機能は git がなくても動きます。
- **少なくとも 1 つの CLI**（インストールしてログイン済みのもの）：

| CLI | コマンド | インストール方法 |
|---|---|---|
| Claude Code | `claude` | [インストールガイド](https://docs.claude.com/en/docs/claude-code/setup) |
| Codex | `codex` | [ガイド](https://learn.chatgpt.com/docs/codex/cli) |
| OpenCode | `opencode` | [ドキュメント](https://opencode.ai/docs/) |
| Antigravity CLI | `agy` | [ガイド](https://antigravity.google/docs/cli/getting-started) |
| Pi | `pi` | [pi.dev](https://pi.dev) |

Agent Workbench は CLI を同梱もダウンロードもしません。`PATH` にあるものを見つけて使います。1 つもなければ、その旨を表示し、セッションは開きません。

**対応プラットフォーム**：Windows 11 と PowerShell で開発し、毎日使っています。macOS と Linux でも変更のたびにインストールと起動を自動で確認していますが、日常的にはあまり使われていないため、報告を歓迎します。Linux ではインストール時にターミナルモジュールをコンパイルするので、`python3`、`make`、C++ コンパイラー（Debian と Ubuntu では `build-essential`）が必要です。

## インストールと起動

```bash
npm install -g agent-workbench
```

続いて、作業したいプロジェクトのフォルダーで実行します：

```bash
agent-workbench
```

ブラウザーが、次のようなアドレスで開きます：

```
  URL          http://127.0.0.1:52341/?token=…
```

入り口はこのアドレスだけです。トークンは起動のたびに変わり、アプリは自分のコンピューター（`127.0.0.1`）でしか待ち受けません。

インストールせずに一度だけ試すなら：`npx agent-workbench`。初回は約 60 MB をダウンロードします（大半はターミナルのネイティブモジュールです）。普段使いには、グローバルインストールのほうが適しています。

## キーボードショートカット

| キー | 操作 |
|---|---|
| `Alt+T` | 新しいタブ |
| `Alt+W` | タブを閉じる |
| `Alt+←` / `Alt+→`（または `Alt+PgUp` / `Alt+PgDn`） | 前 / 次のタブ |
| `Alt+P` | 右パネルの表示 / 非表示 |
| `Shift+Tab`（ターミナルの外で） | 直前のタブに戻る |

ヘッダーの `?` ボタンで、アクティブな CLI 自身のショートカットとあわせて、すべてを一覧表示できます。`Alt` を使うのは、ブラウザーが `Ctrl+T`、`Ctrl+W`、`Ctrl+Tab` を自分のタブ用に確保していて、ページに渡さないためです。

それ以外のキー（`Esc`、`Ctrl+C`、`Ctrl+R`、`Ctrl+O`、矢印キー、画像を貼り付ける `Alt+V`）は、そのまま CLI に届きます。`Ctrl+V` も同じで、何が起きるかは CLI 次第です。Windows の下部のコンソールだけは例外で、Windows Terminal と同じく `Ctrl+V` でテキストを貼り付けます。

## オプション機能

### CLI 間の共有メモリ

各 CLI は、プロジェクトについて学んだことを自分の場所に保存するため、ほかの CLI からは見えません。**メモリ**タブでは、すべての CLI に共通の 1 つのメモリを用意できます。プロジェクトの `.agents/memory/` フォルダーに置くノートで、どの CLI も（ここからでも、自身のターミナルからでも）`AGENTS.md` と `CLAUDE.md` を通じて読み書きします。このタブは最初は非表示なので、⚙ 設定から表示してください。

**変更をプレビュー**で、何が書き込まれるかをファイルごとに確認でき、あなたが確定するまで何も変更されません。セットアップすると、Claude Code がそのプロジェクトについてすでに持っていたメモリをインポートします。アプリは各 CLI のグローバル設定を編集しません。貼り付け用のスニペットを表示するので、ご自身で貼り付けてください。

### 履歴のバックアップ

履歴は各 CLI のものなので、CLI が形式を変えたり、古いものを削除したりすることがあり、CLI 自体がアンインストールされることもあります。バックアップは、会話のコピー（メッセージ、ツールの呼び出しと結果、画像、各プロジェクトのメモリ）を、アプリがなくても読めるファイルとして、あなたのフォルダーに保存します。

**既定ではオフです**。プロジェクトのサイドバー上部にあるバックアップのボタンか、⚙ 設定から開きます。**計測**を押すと、何も書き込まずに CLI ごとの必要な容量がわかり、**オンにする**でバックアップが始まります。それ以降は、サイドバーにあるもののうちアーカイブされていないものをすべてコピーし、会話は変更が止まってから 1 分後にもう一度コピーします。そのフォルダーから何かを削除することは決してありません。

バックアップがオンのとき：

- CLI の履歴から消えた会話も、「バックアップ」の印が付いてサイドバーに残り、Markdown として開けます。
- どのプロジェクトも、Markdown にエクスポートできます。
- 複数の CLI がある場合、サイドバーのフィルターで**会話内**を検索できます。対象は、すべての CLI からコピーしたテキストすべてです。

<img src="assets/captura-buscador.png" width="40%" alt="会話内の検索：各 CLI のセッションで 1 件ずつ一致し、それぞれの抜粋が表示されている様子">

既定の保存先は、アプリの設定フォルダー（Windows では `%APPDATA%\agent-workbench\vault`）です。**フォルダーを変更…** を使うと、何も上書きせずに別のフォルダー（同期フォルダーや別のドライブなど）へコピーし、元のフォルダーはそのまま残します。同期フォルダーやリポジトリに置くと、会話も一緒に共有されます。

<details>
<summary>Gemini CLI と Antigravity IDE の履歴のインポート</summary>

1 回限りのインポーターが 2 つあり、アプリが読み取らないツールの履歴を取り込みます。どちらもソースコードから実行し（[後述](#ソースから実行する)）、**`--write` を付けない限り何も書き込みません**。付けなければ、何をインポートするかを表示するだけです。

- `pnpm vault:import gemini-cli [--cwd <folder>]`：Gemini CLI に残っているチャット。`--cwd` には Gemini CLI を使っていたフォルダーを指定し、チャットをそのプロジェクトの下に整理します。

### Antigravity CLI：状態とコンテキストメーター

Antigravity CLI が、作業中かあなたを待っているか、そしてトークンをどれだけ使ったかを伝えるのは、「ステータスライン」を通じてだけです。ステータスラインがなくてもタブは普通に動きますが、タブのドットは状態が不明であることを示し、メーターは空のままです。有効にするには：

1. Antigravity のタブを開き、メーターの横にある**設定**をクリックします。
2. 表示された行をコピーし、`~/.gemini/antigravity-cli/settings.json` の既存の内容に追加します。アプリはこのファイルを編集しません。編集するのはあなたです。
3. 数秒以内に、または**確認**を押すと、ダイアログに**設定済み**と表示されます。

この行は、アプリ自身のフォルダーにある小さなスクリプトを実行します。スクリプトが保存するのは各会話の状態、モード、モデル、トークン数だけで（CLI から一緒に渡されるメールアドレス、クォータ、プラン、コストは保存しません）、何も出力しないので、CLI 自身のステータスラインはそのままです。一度設定すると、アプリの外で開いたものも含めて**すべての** `agy` セッションで実行されます。また、`PATH` に `node` が必要です。

### SSH によるリモートアクセス

Agent Workbench を 1 台のコンピューターで動かしたまま、同じネットワーク上の別のコンピューターから、そのブラウザーで使えます。そちらに CLI をインストールする必要はありません。**アプリがネットワークに公開されることはありません**。待ち受けるのは引き続き `127.0.0.1` だけで、もう一方のコンピューターは SSH トンネルを通じて接続します。このトンネルは、動作に欠かせないものでもあります。トンネルを通すと、もう一方のブラウザーからはアプリが `localhost` として見えます。ブラウザーがクリップボードや通知を使えるようにするには、これが条件になるからです。**既定ではオフです**。

**1. アプリを動かすコンピューターで一度だけ：SSH サーバーをオンにします**。管理者権限が必要なシステムの変更なので、アプリは代わりに行いません。

- **Windows 10/11**：**管理者として**開いた PowerShell で実行します。1 行目はサーバーをダウンロードしてインストールするため、数分かかります。プロンプトが戻るまで待ってください。

  ```powershell
  Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
  Start-Service sshd
  Set-Service -Name sshd -StartupType Automatic
  ```

- **macOS**：システム設定 → 一般 → 共有 → **リモートログイン**。
- **Linux**：ディストリビューションの OpenSSH サーバーをインストールしてオンにします。Debian または Ubuntu の場合：

  ```bash
  sudo apt install openssh-server
  sudo systemctl enable --now ssh
  ```

**2. アプリで：ヘッダーの ⇄ →「リモートアクセスをオンにする」を選び、Agent Workbench を再起動します**。トンネルには変わらないポートが必要なので、アプリは固定のポート（既定は 24837 で、変更できます）を使い、ポートは起動時に決まります。再起動すると開いている CLI は閉じられ、タブはスリープ状態で戻ります。一方、オフにする操作はすぐに反映されます。

**3. もう一方のコンピューターで、使うたびに：トンネルを開きます**。ダイアログに、そのままコピーできるコマンドが表示されます：

```
ssh -N -L 24837:127.0.0.1:24837 you@your-computer
```

実行したままにして、**両端で同じポートを使ってください**。ローカル側のポートが違うと、アプリは 403 を返します。`-o ServerAliveInterval=30 -o ExitOnForwardFailure=yes` を付けると、Wi‑Fi が切れたときにトンネルが固まったままにならず、切断に気づくようになります。Windows では、このコマンドを `.cmd` ファイルに保存しておき、ダブルクリックで実行できます。

**4. そのコンピューターを一度だけペアリングします**。ダイアログの**デバイスをペアリング**を押すと、`http://localhost:24837/?pair=K7QM-X2RD` のような、1 回限りのコード付きのアドレスが表示されます。5 分以内に、もう一方のコンピューターのブラウザーで開いてください。それ以降、そのブラウザーは `http://localhost:24837` を開くだけで使えます。アプリを再起動しても同じです。ダイアログにはペアリング済みのデバイスが一覧表示され、**取り消す**を押すと、そのデバイスをすぐに切り離せます。

ペアリング済みのデバイスでは、アプリのすべての機能を使えます。ただし、リモートアクセスの管理と、アプリが動いているコンピューターでウィンドウを開いてしまういくつかの操作（「既定のアプリで開く」など）は除きます。ペアリング済みのデバイスであることは、ヘッダーの**リモート**バッジでわかります。アプリにはコンソールがあり、エージェントも起動するので、ペアリング済みのデバイスは、あなたと同じようにこのコンピューターでコマンドを実行できることに注意してください。**ペアリングするのは自分のデバイスだけにしてください**。

**スマートフォンやタブレットの場合**：同じトンネルを通すと、スマートフォンのブラウザーでは 1 列のレイアウトになります。プロジェクトのサイドバーは横からスライドして現れ、タブはヘッダーに並び、帯状のバーで会話、CLI、変更、ファイルなどを切り替えます。このレイアウトは、幅が 768 px 未満のウィンドウならどこでも表示されます。タッチスクリーンでは、入力欄の Enter で改行し（送信は送信ボタンで行います）、ターミナルの上を指でドラッグするとスクロールします。

<details>
<summary>トンネル専用の、より安全な SSH 鍵（推奨）</summary>

SSH のログインはそのコンピューターでのあなたのユーザーとして行われるため、トンネルを開けるパスワードや鍵があれば、そこで完全なターミナルも開けてしまいます。トンネルにしか使えない鍵を作ることができます。もう一方のコンピューターで鍵を生成し（`ssh-keygen -t ed25519`）、その公開鍵を、アプリを動かすコンピューターの `authorized_keys` に、先頭に次のオプションを付けて追加します：

```
restrict,port-forwarding,permitopen="127.0.0.1:24837",command="exit" ssh-ed25519 AAAA… other-computer
```

`restrict` だけでは、その鍵でまだコマンドを実行できます。その扉を閉じるのが `command="exit"` で、トンネルにコマンドは必要ありません。Windows では、ユーザーが管理者ならファイルは `C:\ProgramData\ssh\administrators_authorized_keys` で、書き込めるのを Administrators と SYSTEM だけにしておく必要があります。管理者でなければ `%USERPROFILE%\.ssh\authorized_keys` です。確認するには、その鍵で `ssh you@your-computer whoami` を試してください。何も表示されずにすぐ終了し、一方で `-N -L` のトンネルは動き続けるはずです。

</details>

### Android アプリ

Android 10 以降向けのアプリがあり、トンネルを自動で開いて、あなたのコンピューターが配信する同じインターフェースを、スマートフォン向けのレイアウトで表示します。バックグラウンドでも接続を保ち、画面がオフでも、エージェントが完了したときやあなたを待っているときに通知します。通知をタップすると、そのタブが開きます。Wi‑Fi が戻ると、自動で再接続します。

リモートアクセスがオンで、コンピューターの SSH サーバーが動いている必要があります（上の手順 1 と 2）。[Google Play](https://play.google.com/store/apps/details?id=io.github.cvelasquez.agentworkbench) から入手するか、[`CONTRIBUTING.md`](CONTRIBUTING.md#the-android-app) の説明に従って [`android/`](android/) から自分でビルドしてください。

**ペアリング（一度だけ）**：

1. ⇄ のダイアログで**スマートフォンをペアリング**を選びます。このコンピューターのターミナルに貼り付ける行と、QR コードが表示されます。Windows でユーザーが管理者の場合、その行は**管理者として**開いた PowerShell に貼り付けます。ダイアログにもそう表示されます。
2. その行を貼り付けます。これで、スマートフォンの鍵がトンネル専用として許可されます。この鍵で届くのはアプリだけで、ターミナルもコマンドも使えません。
3. アプリで QR コードを読み取ります。コードは 1 回だけ、5 分間有効です。スマートフォンが接続するまで、ダイアログは開いたままにしておく必要があります。

QR コードには、スマートフォン用の SSH 秘密鍵が入っています。コンピューターはスマートフォンが使うまでそれをメモリ上にだけ保持し、ディスクには決して書き込みません。**この QR コードの写真を人と共有しないでください**。スマートフォンは最初の接続でコンピューターの SSH フィンガープリントを記憶し、それが変わった場合は接続を拒否して知らせます。

**スマートフォンを外すには**、ダイアログで**取り消す**を押し、`authorized_keys` からその行（末尾が `agent-workbench-phone` の行）を削除します。スマートフォン側では、**設定 → このコンピューターを削除**で、その鍵と認証情報が削除されます。

スマートフォンの待機中に通知が遅れて届く場合は、アプリをバッテリーの制限なしで動かしてください：**設定 → アプリのバッテリー設定を開く**。アプリがスマートフォンに保存するものと、要求する権限は [`PRIVACY.md`](PRIVACY.md) にあります。

## データとセキュリティ

- **Agent Workbench は、どこにも何も送信しません**。テレメトリーも分析もなく、アプリ自身がネットワーク通信を行うこともありません。Android アプリが通信するのは、あなたのコンピューターだけです。
- **各 CLI は、手動で開いた場合と同じことを、これまでどおり自分で行います**：AI プロバイダーと通信し、更新を確認したり、自身の利用データを送信したりすることがあります。Agent Workbench はそこに何も加えず、それをオフにすることもありません。どの CLI の設定も変更しないからです。各 CLI が何を送信するかは、それぞれのドキュメントに書かれています。
- **認証情報には一切触れません**。ログイン画面はありません。CLI からログインを求められたら、その CLI のターミナルでログインします。アプリはそれに気づきもしません。
- **CLI の履歴を読み取りますが、CLI のフォルダーには何も書き込みません**。何を読み取り、何を決して開かないかは、下の表のとおりです。
- **書き込むのはアプリ自身のフォルダーだけです**。プロジェクト内に書き込むのは 1 つだけで、それもあなたが確認した場合に限ります：共有メモリです。
- **サーバーはあなたのコンピューター上（`127.0.0.1`）でのみ待ち受けます**。ポートはランダムで、起動のたびに新しいランダムなトークンを使い、ほかの Web ページからのリクエストは拒否します。リモートアクセスでもこれは変わりません。ポートが固定になるだけで、待ち受けは引き続き `127.0.0.1` 上です。残りは、あなたがオンにして管理する SSH が担います。
- **「変更」パネルは読み取り専用です**。コミットも、ステージも、プッシュもできません。エージェントがファイルを編集している中で履歴を書き込むボタンがあると、あとで誰が押したのか誰にもわからなくなる、まさにそういうものになるからです。

| CLI | 読み取るもの | 決して開かないもの |
|---|---|---|
| Claude Code | `~/.claude/` から：`projects/`（履歴と、インポート用の各プロジェクトのメモリ）、`sessions/`（CLI があなたの応答を待っているかどうか）、`plans/`。「プラン」タブのために、会話がプロジェクト内やそのセッションの一時フォルダーに書いた `.md` ファイルも読みます。ただし**表示中の会話が名前を挙げたものだけ**で、フォルダーを見て回ることはありません | `.credentials.json` やあらゆるトークン |
| Codex | `~/.codex/`（または `CODEX_HOME`）から：`sessions/` と `archived_sessions/` | `auth.json`、`config.toml`、その `*.sqlite` データベース |
| OpenCode | 読み取り専用で開く `opencode.db` データベース（その中のセッション、メッセージ、パートだけ）と、コンテキストウィンドウのサイズを知るためのモデルカタログ | `auth.json`、`opencode.json`、アカウント・認証情報・権限・共有セッションの各テーブル |
| Antigravity CLI | `~/.gemini/antigravity-cli/` から：各会話のトランスクリプト、`history.jsonl`、各フォルダーの最後の会話、`settings.json` のモデルとステータスライン、会話インデックスの一時的な**コピー**。`~/.gemini/config/projects/` から：各プロジェクトのフォルダー | MCP の設定、システムのキーチェーン内の項目、`conversations/` の中身、そして IDE である `~/.gemini/antigravity/` |
| Pi | `~/.pi/agent/`（または `PI_CODING_AGENT_DIR`）から：`sessions/` のセッションと、コンテキストウィンドウのサイズとモデルの選択に使うモデルカタログ `models-store.json`。インストール済みの Pi パッケージから：Pi を実行せずにバージョンを知るための `package.json` と、組み込みのモデル一覧 | `auth.json`、`models.json`、`settings.json`、MCP の設定 |

[バックアップのインポーター](#履歴のバックアップ)を実行した場合は、その節に書かれているものも読み取ります。ファイルごとの完全な一覧は [`ARCHITECTURE.md`](ARCHITECTURE.md#4-what-is-read-from-each-cli) にあります。

<details>
<summary>細かい注意事項：残る痕跡、環境変数、アプリが書き込むもの</summary>

**知っておきたい 3 つの痕跡**：

- **OpenCode のデータベースを読み取ると**、SQLite がどの読み手に対しても行うことが起きます。`-wal` と `-shm` のファイルがなければ作成し、`-shm` の日付を更新します。読み取るために OpenCode のコマンドを実行することはありません。
- **Antigravity のタブ自身のログが見つからない場合**、アプリは CLI の `log/cli-*.log` ファイルを読みます。これらにはあなたのメッセージやアカウントのメールアドレスが含まれますが、読むのは会話の ID を見つけるためだけで、どの行も保存しません。
- **OpenCode では、アプリがローカルの OpenCode サーバーを起動します**（`opencode serve`）。起動するのは 1 つだけで、最初の OpenCode タブを開いたときから、最後のタブを閉じて 5 分後まで、またはアプリを閉じるまで動きます。OpenCode の設定がどうなっていても、`127.0.0.1` のランダムなポートで、起動のたびに異なるパスワードを使って待ち受けます。アプリがこのサーバーに求めるのは、セッションの状態、保留中の許可と質問、セッションの作成、質問への回答、セッションの停止だけです。設定やアカウントについては何も求めません。

**環境変数**：CLI はあなたの環境をそのまま引き継ぎ、ログイン用の変数は追加されません。例外は 2 つです。アプリは履歴の保存を無効にしてしまう `CLAUDE_CODE_CHILD_SESSION` を**削除**し、削除したときはバナーで知らせます。また、OpenCode サーバーには、起動ごとのパスワードを入れた変数 `OPENCODE_SERVER_PASSWORD` を 1 つ**追加**します。これはどのアカウントのパスワードでもなく、どのタブの環境にも入りません。各 OpenCode タブはこのパスワードをコマンドライン（`attach --password`）で受け取り、そこでは同じユーザーとして動くほかのプログラムから見えます。有効なのはそのサーバーに対してだけで、アプリを閉じると使えなくなります。

**Pi が自分で送信するもの**：Pi は起動時に、pi.dev で最新バージョンとモデルカタログを確認し、インストールと更新のたびに、そのことを pi.dev に報告します。この報告をオフにするのは、ここではなく Pi の側です：Pi の設定で `enableInstallTelemetry: false` とするか、環境変数 `PI_TELEMETRY=0` を使います。

**アプリが書き込むもの**：

- **アプリ自身の設定フォルダー**：開いているタブ、インデックスのキャッシュ、メモ、アーカイブしたセッション、未送信のメッセージ、Antigravity のステータスライン用スクリプト、そしてオンにした場合はバックアップ（または選んだフォルダーに）。リモートアクセスがオンなら、ペアリング済みのデバイスの一覧も保存します。中身は各デバイスの名前、2 つの日付、認証情報のハッシュで、認証情報そのものは決して保存しません。
- **一時フォルダー**：貼り付けたり添付したりした画像とファイル。Antigravity の各タブのログ（あなたのメッセージを含み、あなただけが読めて、24 時間を過ぎたあとの最初の起動で削除されます）。別の CLI で続けた会話のトランスクリプト（そのタブを閉じたとき、または 24 時間後に削除されます）。
- **プロジェクト内（1 つだけ、確認した場合のみ）**：共有メモリ。書き込むのは `.agents/memory/`、`AGENTS.md` と `CLAUDE.md` のマーカーの間、`.gitignore` の末尾の数行に限られます。

</details>

## トラブルシューティング

**「PATH に『claude』コマンドが見つかりませんでした。」のあとに「次の CLI にも対応しています：…」と表示される**。アプリが CLI を 1 つも見つけられませんでした。Windows では `where claude`（それ以外では `which claude`）で確認し、`codex`、`opencode`、`agy`、`pi` も同じように確認してください。CLI は起動時に探すため、アプリを開いたまま CLI をインストールした場合は、アプリを再起動してください。

**Pi をインストールしたのに、アプリが認識しない**。アプリは Pi を見つけるために `pi` を実行しません。コマンドの隣にある Pi のパッケージからバージョンを読み取ります。この方法が使えるのは、Pi を npm または pi.dev のインストーラーでインストールした場合です。単体の `pi` バイナリは認識されません。また、`pi` という名前の別のプログラムが `PATH` で先に見つかる場合、アプリはそれを無視し、そのことをコンソールに表示します。

**Pi のタブで、入力欄に「CLI があなたの応答を待っています。」と表示される**。Pi が、プロジェクトのフォルダーを信頼するかどうかを尋ねています。**CLI** タブで回答してください。アプリが代わりに回答することは決してありません。

**OpenCode の履歴が表示されない**。アプリの起動時に出る `History` の行を見てください。その Node のバージョンには `node:sqlite` が含まれていないと書かれていれば、Node を 22.13 以降に更新してください。その行がなければ、データベースが見つかっていません。データベースは `~/.local/share/opencode/opencode.db`、または `OPENCODE_DB` か `XDG_DATA_HOME` が指す場所にあります。

**OpenCode のタブが開かず、「Couldn't start the OpenCode server」と表示される**。原因はコロンのあとに書かれています。それでもわからなければ、普通のターミナルで `opencode` を開いてみてください。そこでも起動しないなら、問題はその OpenCode のインストールにあります。

**OpenCode のタブに、サーバーが終了したと表示される**。同じバーにある**再起動**を押すと、別のサーバーを起動して、タブを同じセッションに再接続します。

**Antigravity のタブに状態やメーターが表示されない**。アプリの起動時に、その CLI の下に出る `Status line` の項目を見てください。未設定、または別のステータスラインがあると書かれていれば、[こちらの手順](#antigravity-cli状態とコンテキストメーター)に従ってください。設定したのに CLI のターミナルに `Statusline Error` と表示される場合は、おそらくそのセッションの `PATH` に `node` がありません。

**インストール時に `node-pty` がコンパイルできない**。これはターミナルのネイティブモジュールです。通常はビルド済みのバイナリをダウンロードしますが、お使いの Node とプラットフォーム向けのものがなければ、コンパイルが必要です：

- **Windows**：「C++ によるデスクトップ開発」ワークロードを入れた Visual Studio Build Tools と、Python 3。（npm の `windows-build-tools` は、もうメンテナンスされていません。）
- **macOS**：`xcode-select --install`。
- **Linux**：`build-essential` と `python3`。

**ターミナルが空白のままになる**。既定のレンダラーは、意図的に canvas にしています。WebGL だと、Windows 11 + Chrome でタブが固まるためです。それでも WebGL を試すなら、アドレスに `?renderer=webgl` を追加してください。

**`CLAUDE_CODE_CHILD_SESSION` を削除したというバナーが表示される**。アプリを Claude Code のセッションの中から起動しています。この変数は履歴の保存を無効にするため、アプリが削除して、そのことを知らせています。普通のターミナルから起動すれば、この表示は出ません。

**もう一方のコンピューターから `ssh` で接続できない**（タイムアウトする、または拒否される）。アプリのあるコンピューターで SSH サーバーが動いていないか、2 台の間にある何かが接続をブロックしています。Windows では、Wi‑Fi ネットワークが「プライベート」に設定されているか確認してください。SSH サーバーのファイアウォール規則が「パブリック」ネットワークを対象にしていないことがあります。ローカルネットワークをブロックする会社の VPN も、接続中は通信を遮断します。`ssh` があなたのユーザーを受け付けない場合、Microsoft アカウントや職場のアカウントでは、ユーザーフォルダーの名前（`C:\Users\<name>`）と、PIN ではなくアカウントのパスワードが必要なことがあります。

**もう一方のコンピューターで、ページに「Origin not allowed」と表示される**（403）。コンピューターの名前や IP アドレスで開いています。トンネルの両端で同じポートを使ったうえで、`http://localhost:<port>` を開いてください。

**もう一方のコンピューターで、ページにセッショントークンがないと表示される**（401）。そのブラウザーがペアリングされていないか、取り消されたか、リモートアクセスがオフになっています。⇄ のダイアログからもう一度ペアリングしてください。

**⇄ のダイアログに、ポートが使用中と表示される**。別のプログラム（多くの場合は 2 つ目の Agent Workbench）がそのポートを使っています。それを閉じて再起動するか、別のポートを選んでください。

**「変更」パネルに、フォルダーが git リポジトリではないと表示される**（実際にはリポジトリなのに）。`PATH` に `git` があるか確認してください。メッセージがそれとは違う場合、それは git 自身のエラーをそのまま表示したものです。

corepack enable pnpm

pnpm build     # インターフェースを一度ビルドする

## 内部の構成

pnpm のモノレポで、すべて TypeScript で書かれています。

```
packages/
  server/    Node, Express, ws, node-pty, chokidar — serves the interface and runs the terminals
    src/agents/   one adapter per CLI: the only part of the server that knows each one
  web/       Vite, React, xterm.js, highlight.js
  shared/    the protocol types, with no `any` at the edges
android/     the Android app, in Kotlin: the SSH tunnel, the interface, the notifications
```

ほかのすべてを形づくっているのは、2 つの決定です。1 つ目は、**ターミナルはサーバー上にあり、ブラウザーはそれを映す窓にすぎない**ことです。ページを閉じても再読み込みしても、作業中のセッションは終了しません。2 つ目は、**汎用のサーバーはどの CLI も名指ししない**ことです。各 CLI について知っていること（どこに何を置くか、どう起動するか、何を読み取り、何を決して開かないか）は、その CLI のアダプターにあり、インターフェースは、その CLI が宣言する内容に応じて各コントロールを表示します。

[`ARCHITECTURE.md`](ARCHITECTURE.md) には厳守するルールとコードの地図、[`CONTRIBUTING.md`](CONTRIBUTING.md) にはリポジトリでの作業方法、[`SECURITY.md`](SECURITY.md) には脆弱性の報告方法、[`PRIVACY.md`](PRIVACY.md) には収集するもの（何もありません）、[`CHANGELOG.md`](CHANGELOG.md) には各バージョンの変更点が書かれています（いずれも英語）。コードのコメントはスペイン語です。この README のスクリーンショットは、架空のデータを使って `pnpm demo:shots` で作成したものです。
